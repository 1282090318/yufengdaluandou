# 05 UI / HUD 描述

> **权威范围**：玩家在屏幕上看到什么、在哪看到、什么时候出现、怎么操作。
> 不含美术风格定义（→ `00_world.md`），不含音效（→ `06_audio.md`）。
> 代码落点：`scripts/ui/hud.gd`（**竞猜模式**的界面）、`scripts/ui/sandbox_hud.gd`（**沙盒模式**的界面）、
> `scripts/ui/pause_menu.gd`（**三个模式共用**的暂停菜单）、`scripts/ui/start_screen.gd`（开始界面）、
> `scripts/camera/camera_rig.gd`（**2026-10-18** 沙盒与生存战斗中的操控准星和状态条）——
> **全部控件由代码构建，没有 .tscn**；两边共用的外观（选项按钮 / 兵种小卡 / 齿轮 / 字号与调色板）
> 在 `scripts/ui/ui_style.gd`。

## 1. 设计原则

1. **HUD 是补充，不是主体**：关掉界面，比赛本身仍然好看。
2. **常驻信息 ≤ 3 组**：顶栏左侧三项（轮次 / 点数 / 观望机会）。
3. **颜色编码全局唯一**：0 队红 `(0.95,0.36,0.34)`，1 队蓝 `(0.38,0.68,0.98)`，警告橙 `(0.98,0.72,0.25)`，成功绿 `(0.40,0.93,0.50)`（代码：`ui_style.gd#COLOR_TEAM` / `COLOR_WARN` / `COLOR_OK` —— ⚠️ 2026-09-25 起**三套 HUD 共用这一份**，原先住在 `hud.gd`）。
   ⚠️ **这一组是 HUD 面板自己的调色板**，与**世界里的队伍色**是**两套不同的值**：3D 场景（模型 / 出生区染色 / 地砖 / 看台前缘 / 队旗 / 单位血条）用 `00_world.md#4.3` 的
   `GameConfig.TEAM_META` —— 0 队 `(0.85,0.24,0.22)`、1 队 `(0.20,0.52,0.90)`。**别把两套当成同一份**（2026-09-19 排查血条配色时踩过这个坑，见 `99_decisions.md` 同日条目）。
4. **不遮挡焦点**：下注面板固定在**屏幕底部横铺**，**右下角只留一行操作提示**，屏幕中上部留给战场。
   ⚠️ 2026-09-19 用户："**移除屏幕右下角的字**" ⇒ 原先"常驻右下"的**属性条整条删除**（见 §2）。

## 3. 下注面板

### 3.1 结构

- 标题：`押注：选一支队伍`（与"本轮投入"同行显示，省一行高度）
- 投入行：`本轮固定投入 2,000`；**第 3 轮起**追加 `全力支持已开放：ALL = 12,000（押中额外奖励 ×2）`
- 每队一张卡片（**左右并排**，0 队左红框；1 队右蓝框），卡片上只放两样东西：
  - 队名
  - 名单（`剑盾兵×3 · 长矛兵×1 · 短弓手×3`）+ 一个按钮 `支持（投入 N）`
  > 2026-09-18（任务 6.2 / 6.3）：卡片上的 `总权重 N / 本轮预算 N` 行、`系统倾向` 标记、
  > 权重构成明细**全部删除**——它们把"读名单"这个核心决策挤成了小字。
- 三个**全局**按钮（与队卡无关，居中排在面板底部）：
  `全力支持 ALL`（**开关**：按下后任一「支持」即按 ALL 下注，再按一次取消。⚠️ **2026-09-19 起每一轮都要重新选择**：
  押注阶段一开始开关自动复位，押完这轮想再 ALL 必须重新按 —— 见 `03_rules.md#3`）
  / `观望` / `自由视角`
- **ALL 的彩光反馈**（2026-09-19 用户："按下全力支持按钮后，选择押注的两个按钮会冒彩光特效"）：
  开关按下时，**两张队伍卡上的「支持」按钮**边框沿色相环循环（0.45 圈/秒，两卡错开半圈）+ 同色外发光，
  提示"这一注是 ALL"；关掉开关 / 押注后 / 换轮时立刻撤掉。实现 `hud.gd#_update_all_in_glow`，
  **只改按钮样式、不碰任何玩法数据**（R-07）。
- 底部提示：规则一行说明
- ⚠️ **2026-09-19：属性条（下面这段的全部内容）已整条删除**（用户："移除屏幕右下角的字"）。
  以下几行**只作历史记录**，代码里已不存在（`hud.gd` 的 `_stat_labels` / `SKILL_NAMES` / `_refresh_stats()`
  都已移除，只剩 `_refresh_ctrl_hint()` 填那一行操作提示）：
  - 原格式：`剑盾兵 W1 | HP 300 | 伤害 34 | 攻速 0.90 | 射程 1.8m | 移速 2.9 · 盾可挡正面来箭`；
  - 原词条（`extra`）：`盾可挡正面来箭` / `命中击退` / `扇形攻击` / `落地范围伤害` / `直击 140 / 溅射 70`（⚠️ 2026-09-25 第五条由 160 / 80 改回，同日还给落点加了**眩晕 1**） /
    `击退带伤害` / `技能：冲撞（冷却 8s）` / `盾牌猛击（冷却 3s）` / `技能：炎爆（无冷却）`；
  - 原技能名表 `hud.gd#SKILL_NAMES`：`charge` → 冲撞 / `rocket_jump` → 火箭跳跃 / `flame_burst` → 炎爆
    （连同上面"① 硬编码 → 按 `skill` 取值、② 改表驱动"两次修正一并作废）。

### 3.4 三个全局按钮的外观与"面板高度不许变"（2026-09-25）

> 用户先要求："**将竞猜模式的全力支持、观望和自由视角的按钮变成沙盒模式的同款**"；
> 随后又要求："**竞猜模式的下注面板保持原来的大小不要变，将面板大小改回去**"。
> 两条一起构成本节口径 —— 外观同款，**尺寸服从面板**。

| 项 | 口径 |
| --- | --- |
| 外观（照沙盒「自由视角」那一档） | `UiStyle.decorate_chip()` + `apply_chip_hover()`：深灰底 + 边框；三者**等宽 280**。⚠️ **2026-10-01**：悬停不再放大。`CHIP_GROW` = **1.0**，只改字色，边框宽度也不再跟着变。旧口径「原地放大 1.17 倍」作废 |
| ⚠️ 高度与字号**不跟沙盒** | 沙盒那档是 **280×44 / 字号 18**，这里必须是 **280×36 / 字号 16** —— 理由见下面两行 |
| 面板高度是**内容撑**出来的 | 声明高度是 230（`offset_top = -286` / `offset_bottom = -56`），但内容（列最小高 223 + 内边距 24）**本来就是 247**；`PanelContainer` 按内容长大、`grow_vertical = BEGIN` 让它**向上**长 |
| ⚠️ **按钮行每高 1 px，面板就高 1 px** | 实测：行 44 ⇒ 面板 255；行 36 ⇒ **247 = 原来的高度**。所以"面板大小不变"直接决定了按钮行只能是 36 高 |
| ⚠️ 为什么字号也得回到 16 | 中日韩字形的行高 ≈ **1.4 × 字号**：小卡那档 18 号 + 小卡内边距（上 6 下 6）⇒ 内容高 **38** ⇒ `custom_minimum_size` 给 36 也只会排到 38（实测）⇒ 面板白白高 2 px |
| ⚠️ 一条踩过的坑（留在这里防复发） | 插入 `Hud._decorate_action_button()` 时，把 `_build_bet_panel()` 末尾那三行 `_hint_label` **误吞进了新函数体**（缩进恰好一致）⇒ **每装扮一个按钮就多造一个"空提示标签"塞进面板列** ⇒ 面板列里凭空多出 **2 个空标签 + 2 条间隔 = 52 px**（叠加按钮行的 +8 px，面板从 247 涨到 307）。⇒ **改这一块之后必须量一次**：`_bet_col` 的子节点数应当只有 **4** 个（标题行 / 队卡行 / 按钮行 / 提示行），面板高度应当 **247** |

### 4.1 结算浮层文案

| 情形 | 标题 | 正文 |
| --- | --- | --- |
| 有胜方 | `<胜方>胜利！`（该队颜色） | `打败<负方>`，下一行是押中 / 押错 / 平局 / 本轮观望，加上投入、点数、观望次数 |
| 没有胜方 | `平局`（灰） | `双方同时倒下`，下一行仍是这一注的结果 |
| 结束且这场有胜方 | 仍是 `<胜方>胜利！` | 第二行写达成「点生点」/ 破产出局 / 观赛结束，以及最终点数、最高点数、押中局数 |
| 结束且没有胜方 | 达成「点生点」/ 破产出局 / 观赛结束 | 同一行再写一遍这个收尾，加上最终点数 |

⚠️ **2026-10-23** 不再在屏幕中间放一块面板和按钮。节点是 `HoldTop` / `HoldTopBox` / `OverlayTitleLabel` / `OverlayBodyLabel` / `HoldBottom` / `HoldPrompt`（「按[Enter]继续」）。`mouse_filter = IGNORE`，不挡镜头。三个模式共用 `UiStyle.make_battle_banner()`。

### 9.1 时机与流程

| 时刻 | 发生什么 | 谁在管 |
| --- | --- | --- |
| 启动瞬间 | 整屏**全黑**；背景那场演示战斗在**黑幕后面真打约 0.9 s**，一有人挨打就**整体冻住** | `StartShowcase` |

| 渐亮结束 | 选项才**可点**（`_input_ready` 置真）。在那之前黑幕虽铺满全屏，但它是 `mouse_filter = IGNORE`、按钮虽在却没人拦 ⇒ **"对着黑屏乱点"不会跳过开始界面** | `StartScreen._process` |

| 点「返回」（2026-09-25 新增） | **就地退回第一档**（亮回「开始游戏 + 继续游戏 + 设置 + 图鉴」、收起另外两档）：不换场、不渐黑、也不 `queue_free()` —— 它只是"改主意了"的出口 | `StartScreen._on_back_pressed()` |
| 点某个模式 | 这一模式已有存档时，先问「这会删除原来的存档并新开一局。」确定才继续，取消留在这一档。沙盒不问。然后按钮被"**打飞**"出画（向右挪一小段 → 被反向加速度扫出左边，见 §9.5），**背景演示相机同时向中心推近**；随后 **渐黑**（620 ms）→ **黑透那一刻**按所选模式装配真比赛（竞猜：`Arena` / `CameraRig` / `Game` / `Hud`；沙盒：`Arena` / `CameraRig` / `Sandbox` / `SandboxHud`；**肉鸽：`Arena` / `CameraRig` / `Roguelike` / `RoguelikeHud`**）并**立即释放背景演示** → **渐亮**（760 ms）。新的一局开始时删掉该模式原来的存档 | `StartScreen._on_mode_pressed()` / `_tick_fly_out()` / `StartShowcase.begin_zoom()` / `main.gd#_on_screen_blacked_out` |
| 点继续档里的模式（2026-10-22） | 不先问。发 `resume_selected`，同样打飞、推近、渐黑。黑透后按存档装配，不走新开一局 | `StartScreen._on_resume_pressed()` |

### 9.3 背景演示（`StartShowcase`）

- **与真场地完全隔离**：自己的地板 / 天空 / 灯光 / 相机，**一个 `Arena` 都不建**；换场时被整棵 `free()`。
  配色见 `00_world.md#4.2`（灰地板 `(0.52,0.53,0.55)`、**更暗**的灰天空 `(0.24,0.25,0.28)`）。
- **固定代表性阵容**（4 v 4，刻意**只挑没有技能的兵种**）：0 队 剑盾 / 长矛 / 短弓 / 扇子；1 队 剑盾 / 长矛 / 长弓 / 扇子。
  ⚠️ 有技能的那几个会在预演里立刻放技能（骑士冲撞 / 狂战士跳跃 / 火焰拳炎爆把人打散、轻骑兵冲刺以 14 m/s 冲出画面），
  冻住时就不是"两队在打架"而是一地散兵 —— 要换阵容请连这条一起考虑。
- **"静止"是怎么来的**：先让它们**真打**（打开 `Unit3D.active`，等同真比赛里 `Arena.start_match()` 对每个单位做的事），
  等**第一次挨打**（判据只用公开的 `hp < max_hp`，而命中帧正好是挥砍动画的顶点）就把整棵战斗子树
  `process_mode = DISABLED` ⇒ 画面完全静止、不再推进任何玩法状态。**镜头不在那棵子树里**，所以照样转
  （实测：冻结后 0.5 s 内位移 **0.000000 m**，同一段时间镜头 **Δyaw = 0.079 rad**）。
  ⚠️ **冻住之前先统一 `heal_to_full()` 回满血**（2026-09-25 用户报的 bug："开始界面不知道为什么有兵种扣血了（如图）"）：
  "打到第一下"只是**为了拿到挥砍顶点的姿势**，不该让背景里留下带伤的兵 ⇒ 冻住那一刻把 8 个演示兵的血
  恢复满、血条随之隐藏，**姿势保持不变**。⇒ 因此开始界面背景里**永远不会出现血条**（血的显示条件就是"未满血"）。
- **环绕镜头**：pivot 在单位群中心，半径 **9.5 m**、高 **3.4 m**、**9°/s（约 40 s 一圈）**，视线焦点抬到 1.1 m。
- ⚠️ **两个已知取舍**：① 演示里的弓手拿不到 `_arena()`（`unit3d.gd#_arena()` 按 `has_method("spawn_arrow")` 找场地）
  ⇒ **只拉弓、不放箭**（背景是静帧，观感无碍）；② 演示靠 `Unit3D.active` 这个开关才会开打，
  它**只作用于这 8 个演示兵**：不 emit `Events.unit_spawned`、不进任何名单、不碰 `GameConfig`。

### 10.3 暂停的实现（⚠️ 这一条最容易做错）

| 项 | 口径 |
| --- | --- |
| 暂停方式 | **`get_tree().paused = true` 整棵树暂停**：单位 / 兴奋圈 / 镜头 / 计时全停（用户选的口径） |
| 菜单为什么还能点 | 整个 HUD 是 `PROCESS_MODE_ALWAYS`（`hud.gd#build()` / `sandbox_hud.gd#build()`）；`PauseMenu` 这一层自己也是 ALWAYS |
| ⚠️ **时间补偿** | 本项目**所有计时都是绝对毫秒**（不变量 I-13），而**树暂停不会停表** ⇒ 暂停 N 秒后，赛程倒计时、出手与技能冷却、眩晕、冲刺时长都会"凭空过去 N 秒"。所以**玩法侧**（`Game.pause_match() / resume_match()`、`Sandbox` 的同名两份）记账，恢复时调 `core/match_pause.gd#shift_deadlines()` 把**所有绝对截止时刻整体后移 Δ**：`Arena.shift_deadlines()` / `CameraRig.shift_deadlines()` / `Unit3D.shift_deadlines()`（**属性扫描**所有 `_*_ms` 整型字段 ⇒ 以后新增计时字段不会漏）。⚠️ 这份算法**三个模式共用一处** |
| 层号 | `PauseMenu.MENU_LAYER = 5`：**高于 `Hud`（默认 1）**、**低于 `StartScreen`（10）** —— 所以**不再依赖"最后 `add_child`"来压层**（旧版注释里那条"必须最后建"已作废）。⚠️ **2026-09-25**：`SettingsScreen.SETTINGS_LAYER = 20`，盖住开始界面（10）和暂停菜单（5）。⚠️ **2026-10-18**：`CodexScreen.CODEX_LAYER = 21`，再盖住设置。三个数字都写在各自脚本里，界面之间不互相引用常量（见 §12、§15） |
| 鼠标 | 打开时强制 `MOUSE_MODE_VISIBLE`（战斗中光标本来是锁住的）；**关闭时不手动恢复** —— `CameraRig._process` 每帧自己核对一次，战斗阶段会立刻重新锁住 |
| 实测（竞猜） | 暂停 0.9 s 后 `arena.match_start_ms` 后移 **916 ms**、单位出手冷却同步后移；暂停期间单位位移 **0.000000 m** ✓ |
| 实测（沙盒，2026-09-25） | 暂停 0.45 s 后 `arena.match_start_ms` 与单位的 `_progress_ms` 各后移 **+448 ms** ✓；「结束战斗」走完整链路（渐暗 → 黑透那一刻生效 → 菜单渐亮回位）后当时是 `phase = RESULT`、`tree.paused = false` ✓。⚠️ **2026-10-23** 手动结束改为回到 `PLACING`，这一格的 `RESULT` 只留作当时的读数 |

| ⚠️ **按下那一下用"事件自带的位置"** | 起笔取 `InputEventMouseButton.position` 换算地面点（`Sandbox._ground_at(screen_pos)`），**不能**用 `get_viewport().get_mouse_position()` —— 后者是"上一帧的鼠标位置"，在"移过去马上按住"这种快动作下还没跟上：界面命中用事件位置（所以面板没吃掉这一下）、摆兵却用缓存位置（可能落在**底部面板背后**的地面）⇒ 第一个兵被摆在看不见的地方（用户 2026-09-25 报的"选完兵种后刚开始拖动放不出来、要拖一段才出第一个"）。拖动过程中没有事件可用，才读视口位置。⚠️ **右键那一下同理**：`_begin_erase_at_screen(button.position)` 也取事件位置 |
| ⚠️ 为什么拖动**还要**轮询兜底 | 拖动时光标会划过底部兵种栏，那些移动事件**会被界面吃掉**；所以除了在鼠标移动事件上直接摆一笔（更跟手），`Sandbox._tick_paint()` 还**每物理帧**判断"左键还按着吗 + 光标现在指着哪"，不受"谁吃掉了事件"影响。⚠️ **右键扫除共用同一条理由、写法逐条对称**：`_tick_erase()` 每物理帧判断"右键还按着吗 + 光标现在指着谁" |
| ⚠️ 起笔 / 收笔 | 起笔靠**按下**事件（`_unhandled_input` 只收没被界面吃掉的），收笔靠**松开**事件，**并且**每帧兜底核查"左键是否还按着" —— 万一松手那一下被界面吃掉，下一帧也会自己收笔。⚠️ **右键盘按下一路同理**：起手 `_begin_erase_at_screen()`，收手靠松开事件 + `_tick_erase()` 兜底。⚠️ **两个按钮互斥**：任一方向起手时先把另一种收掉（`_begin_paint_at_screen()` 先 `_finish_erase()`，`_begin_erase_at_screen()` 先 `_finish_paint()`） |

开始界面第一档和三个模式的暂停菜单都能打开。代码在 `scripts/ui/codex_screen.gd`（`class_name CodexScreen extends CanvasLayer`）。由打开它的那一层自己 `new()` 并挂在自己下面，「返回」和 `Esc` 只收起自己，底下那一层留着。

### 15.1 入口

| 入口 | 位置 |

### 15.2 看到什么

左列是名单，中间是说明，右边是一块会转的模型。⚠️ **2026-10-23** 标题旁边两颗 `CodexTab_%d`：「兵种」「援助」。打开时停在兵种。名单上方是 `CodexSortRow` 和 `CodexFilterRow`。兵种只有「按价格」（`SortPrice`）：同一权重收成一组，组上写「价格 N」，N 就是权重。援助还有「按种类」（`SortKind`）。打开援助时仍按变种、专家、战场道具、战术模块分组（`AidGroup_<组>` / `AidPick_%d`）；点「按价格」则按补给分组，组上写「价格 N」。筛选默认一颗都不选，名单全显示。兵种可筛「近战」「远程」（`FilterMelee` / `FilterRanged`）。⚠️ **2026-10-23** 远程 = `is_ranged`，再加上持续照射的心灵腐化师和湮灭之瞳。玩法表上的 `is_ranged` 仍只表示会射箭。援助可筛「免费」（补给 0，`FilterFree`）以及四个种类（`FilterVariant` / `FilterExpert` / `FilterProp` / `FilterModule`）。多选是交集。没有条目时名单和说明都写「无」（`CodexEmpty`）。援助这一页不转模型。中间写名字、分组、补给和效果。
