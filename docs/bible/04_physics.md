# 04 物理参数（场地、移动、击退、盾牌）

> **权威范围**：场地尺寸、场地风景、朝向与坐标系（含「横 / 纵」参考系）、移动手感、出手动作（前摇 / 突刺）、碰撞层、击退（含击退期间禁移）、盾牌挡箭的几何判定。
> 玩法数值（伤害、血量、点数）去 `03_rules.md`。

## 1. 引擎物理配置（已定）

| 项 | 值 | 出处 |
| --- | --- | --- |
| 3D 物理引擎 | Jolt Physics | `project.godot` |
| 物理帧率 | 60 Hz | `project.godot` |
| 重力 | 18.0 m/s² | `project.godot` |
| 选手运动模式 | `MOTION_MODE_FLOATING` | `unit3d.gd#_ready` |
| **贴地判定** | **射线自查**（`_grounded()`），不用 `is_on_floor()` | `unit3d.gd#_grounded` |

> 重力只用于让选手贴地。选手不做跳跃，因此不需要可变重力 / 土狼时间。
>
> **为什么不用 `is_on_floor()`**：实测在 Jolt + 扁平胶囊 + 大块地板下，接触法线明明是
> `(0,1,0)`、穿透只有 1 mm，引擎仍返回 `is_on_floor()=false` / `is_on_wall()=true`，
> 于是每帧"施加重力 → 被地板挡住 → 判定不算着地"，水平位移被一起吃掉，
> 表现为**选手站在原地下坠/不动**（bug 2a/2b 的真因）。
> 现在改为从自身向上 0.5 m 向下打 0.75 m 的射线查世界层（mask=1），命中即视为着地。

### 2.1 五条几何约束（违反任意一条都会出现"掉出世界 / 站着不动 / 全员被毒"）

| # | 约束 | 理由 |
| --- | --- | --- |
| G-01 | `FLOOR_THICK` ≫ `TERMINAL_VELOCITY` × 物理帧长（25 × 0.0167 ≈ 0.42 m） | 地板太薄会**穿地**：选手掉到地板下方 → 世界之外 → 永远不落地（bug 2a） |
| G-02 | 同队选手间距 ≥ ~1 m（`SPAWN_MIN_GAP`）；⚠️ **2026-09-19 起巨物自动放大**：实际间距 = `max(1.0, 双方判定半径之和)`，见 §2.3 | 间距过大时后排远程的射线全被前排友军挡住，整队零输出、原地不动（bug 2b） |
| G-03 | ~~兴奋圈免伤宽限~~ | **已废止（2026-10-23）**。圈不再出现，这条约束不再适用 |
| G-04 | 弓手后撤阈值 < 近战射程 | 否则弓手在近战够不到的距离无限风筝（实测阈值 3.2 m 时长矛兵对弓手胜率 0%）。⚠️ 2026-09-17 起这条**已经用"取消后撤"落实**（见 `#3.2`），约束本身仍然有效 |
| G-05 | ~~`RING_START_RADIUS` ≥ `ARENA_HALF_Z`~~ | **已废止（2026-10-23）**。不再做圈内外判定 |

**G-03 的现状**：场地放大到 100 × 50 m、出生点又在后半段之后，
`RING_START_RADIUS` 无法再同时罩住所有出生点（那需要 ≈ 53 m 的半径）。
因此改为**免伤宽限**（`RING_GRACE_MS` = 3 s，不变量 I-14）：
圈出现后 3 s 内谁都不算圈外，给圈外单位回防时间。

> **G-05 的来历（2026-09-18）**：场地从 52×24 放大到 100×50 时，`RING_START_RADIUS` 从 16 调到 **32**，
> 依据**不是**"按面积/长宽比等比放大"，而是这条几何约束：32 = 半深 25 + 7 m 余量（52×24 时代是 16 = 12 + 4）。
> 它同时决定了圈在 X 方向留下的"走廊"半宽，是逼两队互相靠近的唯一机制。
> **任何改动 `ARENA_HALF_Z` 的提交都必须重算这个半径。**
>
> 📌 **用户裁定（2026-09-18）：G-05 不升格为不变量**——`_index.md#2` 的不变量清单保持不变，
> 它继续只是 §2.1 的一条几何约束。改它不需要走"先改 99_decisions"的流程。

### 2.2 边界处理

边界墙**只保留碰撞体、不渲染网格**（`Bounds_north/south/east/west`），场地边界改用地面上的细线表达。
好处：观感上没有"被围住"，但选手与箭矢仍然不会跑出场地。

### 2.3 出生点布局（`GameConfig.make_spawn_layout`）

> 取代旧的"沿 z 轴一字排开"。

| 规则 | 值 |
| --- | --- |
| 出生区 | 己方半场的后半段：`\|x\| ∈ [半宽×0.30, 半宽×0.95]`（即 15.0 ~ 47.5 m） |
| 兵种簇 | 每种兵 1 个簇心；该兵种人数 ≥ 10 时开 2 个 |
| 簇内散开 | 以簇心为中心的**椭圆**：X 方向半径 `max(SPAWN_CLUSTER_RADIUS, 判定半径 × 2.5)`（人形仍是 3.4 m；**巨物自动放大**，2026-09-19），Z 方向再乘 `SPAWN_CLUSTER_ASPECT`（2.5） |
| 个体间距（2026-09-19 改） | 人形仍是 `SPAWN_MIN_GAP`（1.0 m）；**巨物** = `max(1.0, 双方判定半径之和)`（投石车 2.40 / 弩车 2.88 / 沙虫 1.41 ⇒ 两台弩车之间要 5.76 m）。⚠️ 否则判定体一放大，出生瞬间就互相穿插、引擎会在开局把它们弹开 |
| **簇心间距（2026-09-19 补）** | **不同兵种的簇心**之间 = `max(SPAWN_MIN_SEPARATION, 双方判定半径之和 + 1.0)`（`_center_gap_between()`；人形之间仍是 4.0 m）。⚠️ 修 bug：用户报告"有时候会在一瞬间有很多兵都往同一个方向去"——根因就是簇心间距一直是**固定 4.0 m**，而"投石车 2.40 + 弩车 2.88 = 5.28 m"这类组合光半径和就超过它 ⇒ 两个兵种的人一出生就大面积互相穿插，穿透修正 + 动量传递会把一群人朝同一方向弹开。实机验证：混编阵容（投石车 + 弩车 + 4 剑盾兵）最小间距 / 所需间距 = **1.18** |
| 簇心间距 | 不同兵种至少 4.0 m（采样 40 次；失败退回随机点） |
| 个体间距 | 同队至少 1.0 m（防止互相挡射界） |
| 边界夹取 | `|x| ≤ 半宽×0.96`、`|z| ≤ 半深×0.92` |
| 出生高度 | 0.40 m |

**每轮只刷一次（2026-09-18 修 bug）**：阵容在**进入押注阶段**时就用 `make_spawn_layout` 摆好
（`game.gd#_roll_teams`），开赛时（`#_start_round`）**不再重新 spawn**，直接启用场上的单位。

> ⚠️ **修掉的 bug**：`_start_round()` 原先又调了一次 `settle()` + `spawn_roster()`。
> 由于 `make_spawn_layout` 用的是**随机布局**，第二次刷出来的位置和押注阶段看到的不一样——
> 观感就是"**兵种瞬间移位**"。而且它还白白重建了一遍全部单位。
> 实测：开赛前后 **兵数 20→20、丢失 0 个、最大位移 0.0000 m** ✓。
> （`_roll_teams()` 总在 `_enter_betting()` 之前调用，所以场上一定有兵；`_start_round()` 只留了一个
> "`arena.units` 为空时补一次"的兜底。）

**为什么簇是椭圆（`SPAWN_CLUSTER_ASPECT`）**：按 §6 的参考系，倍率乘在 **Z** 上
= 沿**垂直于双方朝向**的方向拉长 → 这是一支**横排（横队）**，正是想要的队形。

`1.0` = 圆形簇；`2.5` = **横排**椭圆：横向理论直径 ≈ 2 × 3.4 × 2.5 ≈ **17 m**，
而正面对进的纵向仍是 2 × 3.4 ≈ **6.8 m**。

实测（60 次采样、10 人单兵种簇）：平均 **横向（世界 Z）跨 11.5 m × 纵向（世界 X）跨 4.9 m，
横向/纵向 ≈ 2.34** —— 队形确实是一横排。

> ⚠️ **观感与参考系（最容易搞混的一处）**：相机默认沿 −Z 看向场地，
> 所以这条**横排**在屏幕上呈现为"自远而近"的纵深，看起来像朝镜头排过来——
> 这是刻意要的效果（2026-09-18 用户裁定），**不是**把队形说成"纵队"的理由。
> "横 / 纵"一律以 §6 的**朝向**参考系为准。
> 屏幕投影实测：`X+20 → 屏幕 x=1129`、`X−20 → 458`、`Z+20 → 屏幕 y=836`、`Z−20 → 277`。

**设计意图**：簇半径（3.4 m）明显大于"互不重叠"所需的间距，所以不同兵种的簇会互相穿插——
用户明确要求"同兵种倾向在一起，但允许其他兵种穿插"。

### 2.4.1 五种战场场景（2026-10-18）

设置里五个勾选，默认全勾。标识是 `forest` / `mountain` / `desert` / `snow` / `city`。一个都不勾，用上面这套灰场地（`plain`）。勾选要按「启用」才写进 `GameConfig`；「退出」不算。

抽一次的时机：⚠️ **2026-10-19** 竞猜**每一轮开始**都抽。第 1 轮在 `setup_first_round()`（含重新开始和再来一局），第 2 轮起在 `next_round()`，清场之后、摆新阵容之前。同一局的十轮会换。沙盒和生存仍是进入这个模式时抽一次。沙盒里反复开战、生存里重开一局，都不换。⚠️ **2026-10-22** 从存档继续时不抽：竞猜用存档里的场景标识把这一轮铺回去，生存用这一回合开始时记下的场景。新开一局仍按上面的时机抽。

换的是地面颜色、天空、雾，以及围墙外的景物。战斗场地的长宽不改，场地里面的地面仍是平的。景物仍是 `MeshInstance3D`，不带碰撞，最近边距边界墙仍 ≥ `ARENA_SCENERY_CLEARANCE`。四面都放，不再把山、楼、冰川和树拦在南侧外面。仙人掌每棵都有两根侧枝；南侧的更矮，侧枝也更短。

| 场景 | 雾 | 天空 | 场地外多出来的 |
| --- | --- | --- | --- |

### 3.2 弓手走位（**无后撤**）

> 2026-09-17（优化 5）起，各兵种走位**完全一致**（技能位移除外，见 `#5.2`）：
> ⚠️ **2026-09-25 起有一处刻意的例外**：**轻骑兵（矛）在冲刺冷却期**走"保持距离的游走"（见 `#5.2`），
> 它据此**不适用**下表 —— 那一条管的是"能打到就站定"，而它在冷却里刻意不要贴上去。

| 行为 | 阈值 | 说明 |
| --- | --- | --- |
| 站定 | 距离 ≤ 射程（短弓手 16 m / **长弓手 28 m**） | 进射程就停下输出 |
| 前进 | 距离 > 射程 | 拉近到射程边缘 |

**为什么取消后撤**：它曾让弓手在近战够不到的距离反向拉扯，观感像"逃跑"。
取消后弓手的补偿来自 §7.1.1（盾牌出手期间失效）。

> **历史决策链**：后撤阈值 0.32 → 0.10 → **取消**。
> 阈值 0.32（5.1 m）时弓手在近战射程之外就后撤，配上最快移速可以无限风筝（长矛兵对弓手 0%）；
> 压到 0.10（1.6 m）后不再无限风筝，但优势度掉到 17~38%（低于 40~60% 判据）；
> 最终改为**取消后撤 + 盾牌出手期间失效**把它拉回 41~63%。

**已知副作用**：短弓手 / 长弓手移速 3.4 m/s **快于近战 2.9–3.1 m/s**，若场上只剩远程互相追不上，
会触发 `DRAW-03` 僵持判平（20 s 无命中）。这是有意保留的安全阀。
> ⚠️ **2026-09-25 注意**：**轻骑兵（矛）的 7.0 m/s 超过了全部远程的 3.4 m/s** ⇒
> 它不会被"跑不掉的远程"拖住；反过来，两台 7.0 m/s 的轻骑兵对峙时靠"冷却期游走 + 7 m 触发"推进，
> 所以它的游走环带（`#5.2`）**必须窄**，否则会变成双方各自后退、谁也打不到谁。

### 3.3 卡住自救（`_start_sidestep`）

选手在 `MOVE` 状态下 **0.4 s 内没能把距离缩短 0.25 m**，就判定为被堵住，**只做横向绕行**：
沿目标方向的垂线走一段，左右交替（`_stuck_switches` 奇偶决定方向）。

被堵住的三种典型场景：友军挡路、顶在隐形边界上、目标被长矛持续击退。
诊断字段：`Unit3D._stuck_switches`（次数越多说明卡得越频繁）。

⚠️ **2026-09-19 优化（用户："弩车、投石车碰撞体积变大后会卡住后面的单位，优化一下使后面的单位能绕过它们"）**
—— 判定体放大之后，0.4 s/0.25 m 那条判据对巨物基本失效（沿着 5.76 m 宽的弩车侧滑时距离仍在缓慢缩短），
而固定的 **0.26 s** 绕行只走 ~0.8 m，单位只会在巨物前面左右摆。两处改动：

| 改动 | 口径 |
| --- | --- |
| **绕行时长按障碍尺寸自适应** | `_start_sidestep(obstacle_radius)`：时长 = `260 ms + max(0, 障碍判定半径 − 0.5) × 420 ms`。人形障碍（0.38）⇒ 仍是 **260 ms**（行为不变）；弩车（2.88）⇒ ≈ **1.26 s**（≈4 m 横移，够绕过去）。⚠️ **2026-09-26 这条式子被换掉了**，见下 |
| **贴到巨物立刻起绕行** | 新增 `_blocking_unit_radius()`：从本帧侧滑碰撞里取"挡路单位"的最大判定半径；`_tick_move()` 里**半径 > 0.5 m 就立即** `_start_sidestep()`（不等 0.4 s 判据），已在绕行中则不重复触发（免得每帧重置时长） |
| **大障碍不左右交替** | 障碍判定半径 > 0.5 m 时**不递增** `_stuck_switches` ⇒ 一直往同一侧绕到绕过去为止（来回换边等于原地摆）；小障碍（友军 / 围墙）保持既有交替行为 |

> ⚠️ **2026-09-26（用户："优化兵种面对巨物的绕路机制（现在兵种可能会在投石车弩车和召唤石柱后左右摇摆）"）**：
> 上面那张表的三条**都还在**，但"左右摇摆"的真因正是它们**互相打架**，四处改动如下 ——
>
> **真因**：侧滑是**垂直于目标方向**的，横移**永远不会缩短到目标的距离** ⇒ 0.4 s 那条进度判据每 400 ms
> 就判一次"没靠近"，把正在进行的侧滑**重启**（`_start_sidestep()` 会 `_stuck_switches += 1` ⇒ **左右对调**），
> 而"贴到巨物立刻绕行"那一条下一帧又用**原方向**把它拉回来 ⇒ 一左一右地摇。
>
> | 改动 | 口径 |
> | --- | --- |
> | **侧滑期间独占走位** | `_tick_move()` 里"在侧滑中"这一支**提前 return**：进度时钟（`_progress_ms` / `_last_dist`）**一直喂到当前帧**，出来之后要重新走满 0.4 s 才再判 ⇒ 那 400 ms 的重启路径**消失** |
> | **起绕那一帧就按新方向走** | 两条触发路径都在当帧直接写 `velocity` 并 `return`（此前会先朝巨物撞一帧、下一帧才横移 —— 贴着盒子表面时那一下读起来像卡顿） |
> | **时长 = 横移距离 ÷ 自己的移速** | `lateral = 障碍判定半径 + 自身判定半径 + UNIT_SIDESTEP_CLEARANCE(0.10 m)`，`ms = lateral / current_speed()` 夹在 `[UNIT_SIDESTEP_MIN_MS(260), UNIT_SIDESTEP_MAX_MS(1800)]`。⚠️ 旧写法"每米半径 420 ms"**隐含"移速 ≈ 3 m/s"**：慢单位（投石车 2.4）绕不动、快单位（轻骑兵 7.0）白绕一大圈。新口径下**一次侧滑正好清过一个障碍**：人形 ≈0.30 s（≈旧值 0.26）、**召唤石柱（1.10）≈0.53 s**（它 2.2 m 宽的盒子需要 ~1.5 m 横移 ⇒ 旧口径要连起两次才过得去）、弩车（2.88）≈0.99 s |
> | **巨物：平时不换边，连绕三次没进展才换** | `_stuck_big_strokes` 计数：巨物**仍然不每次换边**（保留上表那条），但连续 `UNIT_SIDESTEP_BIG_STROKES`(3) 笔都没进展就掉一次头 —— 防"顶着盒子 + 围墙的夹角"死绕。节奏 ≈3 s 一次（读起来是"换个方向再试"，不是摇摆） |
>
> ⚠️ **四个常量全部搬进 `GameConfig`**（`UNIT_SIDESTEP_BIG_RADIUS` / `_CLEARANCE` / `_MIN_MS` / `_MAX_MS` / `_BIG_STROKES`）——
> 旧的字面量（`0.5` / `260` / `420` / `0.26 s`）散在 `unit3d.gd` 里，本来就与不变量 **I-15**"可调参数全部住 `GameConfig`"相抵。
> ⚠️ **小障碍（友军 / 围墙）的交替行为一字未动**（`_stuck_switches` 照旧递增），只是时长跟着各自的移速算了。
> ✅ **实测**：剑盾兵从 (−10, 0) 出发、绕过**石柱（2.2 m 盒）+ 弩车（5.76 m 盒）**去 +12 的靶子 ——
> 13 s 内只有 **4 次**方向切换（每个障碍一次的合理换边），最终抵达并开打（靶子掉 34 血）；
> 旧口径下这两处各会**每 0.4 s 翻一次方向**。

> ⚠️ **这里曾经会"换一个没被堵住的目标"**（`_resolve_stuck` + `_nearest_free_target`）。
> 优化 6 把索敌统一为"只打最近的敌人"之后，换目标会直接违反那条规则——**已删除**。
> 现在被堵住只绕行，绕过去继续打同一个目标。

### 3.4 索敌：只打最近的敌人

**所有兵种一视同仁**：每个物理帧重算一次"场上最近的敌人"，谁近就打谁。
⚠️ **2026-10-18**：被操控的单位不跑这一支。它不锁最近的人。走位、出手和技能方向见 §3.6。

| 项 | 规则 |
| --- | --- |
| 目标选择 | `Unit3D._find_target()` 取存活敌方中距离最近者（按距离平方比较，无开方） |
| 重算时机 | `Unit3D._lock_nearest_target()`，**每物理帧移动前后各一次**（见下） |
| 目标切换 | 目标一变就**取消未完成的这次出手**（清掉"正在出手"的表现态 `_striking`；2026-09-19 攻击节奏重做后，等价物是**断开动画链** `_swing_from_ms = 0`）与卡住检测进度。⚠️ **2026-09-19 改**：不再重置冷却——此前"目标一变就归零"，于是**打死一个敌人 → 锁定下一个 → 冷却被白送一次**，实际攻速明显快于面板（弩车一发秒杀时最夸张）。现在冷却跨目标连续计时。⚠️ **2026-09-19 再补（第三、四个复位点）**：`MOVE → ATTACK`（进入射程）与 `ATTACK → MOVE`（目标出射程）这两处原先也会把出手节奏归零 ⇒ 单位只要走过一次"出射程 → 走回来"就等于**又白送一次冷却**，实际射速退回"前摇"。现在**冷却（`_next_hit_ms`）只在命中那一帧往后推一整格**，任何状态切换都不再碰它（实测出手间隔回到面板值，见 `99_decisions.md` 2026-09-19 相关条目）；⚠️ 但**动画链**会在离开 `ATTACK`（含眩晕）时断开 ⇒ 回到 `ATTACK` 的下一次出手**从头挥**（这正是"每次出手都跟着动画"的保证，见 §3.5） |
| 不变式 | 任何时候 `unit.target` 都应等于"当前最近的敌人"；断言接口 `Unit3D.is_targeting_nearest()`。⚠️ **2026-10-18**：被操控时不跑 `_lock_nearest_target()`。`target` 只在近战准星选中人、或持续照射锁住束内的人时才写上 |

**为什么要锁两次**：`_think()` 在移动**之前**读目标，`move_and_slide()` 之后所有人的位置都变了。
只在移动前锁，会留下"目标相对位置已变"的一帧滞后；移动后再锁一次，目标才反映玩家这一帧真正看到的位置。

> ⚠️ **历史（两条都已删除）**：
> 1. **远程曾优先选"有射界"的敌人**（`_has_line_of_sight`）——那是为了修"短弓手被自家前排挡住就傻站着"。
>    但箭矢本来就**穿过友军**（`arrow.gd#_resolve_segment`），所以那条规则既不必要，又违反"只打最近"。
> 2. **目标曾被缓存**（只在目标死亡时重找）——会让单位咬着跑远的旧目标不放，
>    即使旁边冒出了更近的敌人。实测偏差能到 **4.3~4.5 m**。
>
> 实测结果：改后单帧采样 **19/19 全部锁定最近者**。
>
> ⚠️ **2026-10-02**：比较不再每人扫全场。**开战之后**（竞猜赛程开着，或沙盒 / 肉鸽的互殴时钟已经记下）每物理帧开头把活人放进边长 `UNIT_QUERY_CELL`（**4 m**）的格子，两队各一列。能被锁定的人再按格收成一份名单（潜地、影子形态、余烬不进这份名单）。每个人从**有人的最近一圈**往外看，空格不翻。上一帧的目标先当作目前最近的人；这个人已经释放就不拿来比。还在的人已经比还没查的区域近出 `UNIT_QUERY_SLACK_M`（**2 m**），就停止。选中的仍是当前最近的敌人。攻城模式的内圈 `attack_min_reach()` 仍生效。布兵和押注还没点火时，不重填格子，也不算最近的人。

### 3.5 出手动作（前摇 / 突刺）

> 2026-09-18 新增：前摇比例由"全局唯一"降级为**默认值**，兵种可覆盖；长矛改为**突刺**动作。

| 项 | 值 | 说明 |
| --- | --- | --- |
| `UNIT_WINDUP_RATIO` | **0.30** | 攻击前摇占攻击间隔的比例，**默认值**；前摇结束即**命中判定点** |

**两条规则**：
1. **出手判定用 `attack_reach()`**：`_resolve_attack()` 在生成伤害/箭矢前先比距离，
   超过上限直接不出手；
2. **目标走出上限就退出 `ATTACK`**：`_tick_attack()` 回到 `MOVE`，清掉"正在出手"的表现态（`_striking`），
   并由 `_animate_attack()` **断开动画链**（`_swing_from_ms = 0`）；⚠️ **冷却 `_next_hit_ms` 不动**（不白送一次出手），
   回到射程后按剩余冷却重新起手、且**这一刀从头挥**（见 §3.5）。

> ⚠️ **修掉的 bug（2026-09-18）**：`_tick_attack()` 原先**只判断"目标还活着"、不看距离**，
> 于是目标一走远，单位就留在 `ATTACK` 态**对着空气挥砍**；而 `_resolve_attack()` 的**远程分支原先根本没有
> 距离检查**，所以**短弓手会对着 16 m 外的目标继续放箭**（箭能飞 88 m）——那不是观感问题，是**超射程伤害**。
> 所有兵种共用一个 `_tick_attack`，所以**每个兵种都有**这个 bug。
> `02_entities.md#2.2` 的状态机本来就写明 `ATTACK` 的退出条件是"**目标出射程**/死亡 → `MOVE`"，
> 代码只是漏了前半条。
> 实测：剑盾兵处于 `ATTACK` 且这一口**已经出手**（旧写法是 `_windup_swing = true`；2026-09-19 攻击节奏重做后，
> 等价说法是"动画时钟 `_attack_timer` 已越过 `windup`"）时把目标挪到 30 m 外，
> **2 个物理帧内退回 `MOVE`** ✓。⚠️ 重做后**冷却不再被清零**：退出 `ATTACK` 只是断开动画链（`_swing_from_ms = 0`），
> `_next_hit_ms` 照旧计时 ⇒ 走回来时"这一刀从头挥、但不白送冷却"（见 §3.5）。

> **缩短前摇只影响"进射程后的第一次命中来得更早"，不改变持续 DPS** ——
> 攻击间隔由 `attack_speed` 决定，前摇只是把命中帧从间隔的 30% 挪到 15%。
> 实测：长矛兵从进入 `ATTACK` 到命中只用 **150 ms**（原 300 ms）。
>
> ⚠️ **2026-09-19 重做后的两条硬性质**（用户："攻击速度重定义：将攻击变为类似技能冷却的样子（如原来攻速为 2 则攻击冷却 0.5 s），
> 只要冷却结束就能攻击，所有单位现在的普通攻击都得跟着普攻动画，不要改变所有单位的现有动画"）：

>    且**不补偿**已经过去的冷却（既不白送一次出手，也不再出现"半截动画就命中"）。副作用是**进射程后的第一刀必然等一个完整前摇**：
>    长矛兵仍是 150 ms，剑盾 / 短弓手 / 骑士 / 狂战士是各自间隔的 30%，弩车是 1.5 s（旧模型在"计时器已在半途"时可能更早命中）；

>

> 后者会把每帧抖动累进相位（实测每周期 +8 ms，几十秒后"命中时动画已经过了顶点"）。
> ⚠️ **代价（只影响调试工具）**：冷却走 `Time.get_ticks_msec()`（不变量 I-13），**不受 `Engine.time_scale` 影响** ⇒
> `debug_autoplay` 的 **8× 快进**下"移动快 8 倍、出手仍是实时"，实测单场从 ~23 游戏秒变成 ~60 游戏秒。
> **平衡测量请按 1× 跑**（`debug_balance_stats` 的模拟器自带独立节拍，不受本改动影响）。
> ⚠️ `_windup_swing` 闩锁**已删除**："这一口已经结算"直接由 `_attack_timer >= windup` 推出，`_attack_timer` 也从
> "逐帧累加 `delta`"降级为**只读的动画时钟**（唯一的出手节拍是 `_tick_attack()` 里的绝对时刻比较）。

## 5. 冲量与击退

| 常量名 | 含义 | 值 | 单位 |
| --- | --- | --- | --- |
| `KNOCKBACK_SPEED` | **每单位击退数值的初速**（2026-09-18 改口径：以前它就是初速，值为 15.0） | **7.5** | m/s |
| `KNOCKBACK_DECAY` | 每秒衰减率（lerp 系数） | **13.0** | /s |
| `KNOCKBACK_CD_MS` | 同一选手被击退的最短间隔 | **1000** | ms |

**触发条件**：长矛兵命中。⚠️ **2026-09-19 改**：直接命中**不再**检查 `tap_knockback()` 闸门——闸门只留给"每帧都在跑的动量传递"（见 `#5.1`），否则攻速快的兵种会白丢击退（用户报告"被赋予击退了但并没有被击退"）。

**击退数值**：写在 `GameConfig.PROFILES` 的 `"knockback"` 字段里 —— 长矛兵 **2.0**；
其余兵种没有这个字段（= 0 = 不产生击退）。

**击退距离 = 击退数值 ÷ 目标重量（2026-09-18 新增，不变量 I-26 的第七项）**：
冲量 = `KNOCKBACK_SPEED × 击退数值`，实际位移再除以**被击退者**的重量（`GameConfig.PROFILES[*]["mass"]`）。
所以长矛兵打重量 1 的单位时，等效初速 = `7.5 × 2 ÷ 1 = 15.0 m/s` —— **与改口径之前逐位相同**；
换成重量 2 的单位就只有一半位移。

**方向约定**：沿"长矛兵 → 目标"的水平方向；**y 分量强制为 0**，避免把目标顶到空中。

**击退不产生伤害叠加**：击退是位置效果，伤害照常按单次伤害结算。

**定身期间位移一律冻结（2026-09-25，§2.6 定身的物理侧）**：`Unit3D.is_rooted()` 为真时，
`_add_knockback()` **入口直接返回**（击退 / **动量转移** / 被冲撞推开 三条路都经由它），
并且 `_physics_process()` 里把**已经攒下的 `_kb` 就地清零** ⇒ 本帧既不进"禁移档"也不进"可移动档"，
**水平位移为 0**。⚠️ **只冻结位移**：伤害照常结算（`apply_hit()` 的伤害与击退本来就是两条路）。
⚠️ 与上面那条"**禁移**"（`is_knockback_immobile()`，重量 < 击退数值）是**两件不同的事**：
禁移是"被推着走、但不能自主移动"，定身是"**根本推不动**"。
实机对照（同一发击退数值 8）：无状态位移 **+0.462 m**、**定身 0.000 m**、眩晕 **+0.476 m**（眩晕不免疫击退）。
⚠️ **2026-09-27 第十二轮再加一条免疫来源（肉鸽科技「剑圣」）**：用户口径"**免疫击退**" ⇒
`_add_knockback()` 对剑圣**直接早退**（实测：同一发 10 的冲量，剑圣 |kb| = **0.000**、同队普通剑盾兵 = **10.0**）。
⚠️ **刻意不把它的重量改成 9999**：重量是**面板第七项数值**（I-26），改它等于改了兵种属性；
而"剑圣免疫击退"是它的一条技能特权 —— 与沙虫那种"重量无穷大写在数值表里"是两码事。
⚠️ 只挡位移：伤害照常结算（与定身同一条纪律）。

**禁移条件（2026-09-18 改）**：`自身重量 < 本次击退数值` 时，击退期间**禁止自主移动**，
位移完全由击退速度接管；否则击退只是**叠加**在自主移动上（被推着照常走位）。
⚠️ **2026-09-25 第八条例外（用户："轻骑兵似乎有时候被击退时就停止了冲锋"）：冲刺期间一律按"可移动档"算。**
判据是 `Unit3D._lance_active()`（**只认冲刺本身**，与下面那个 `is_mid_dash()` 不是一回事，见 `08_naming.md#3.3`）；
此时击退从"整体覆盖 `velocity`"降级为"叠加"。根因：禁移档在 `_physics_process` 里**两次**用 `_kb`
覆盖 `velocity`，而**第二次在 `_think()` 之后** —— 冲刺刚写好的 14 m/s 会被当场冲掉，单位只能被推着走。
⇒ **被推是真的（位移照常发生），但冲锋不会断**：它一边被推一边继续朝目标冲。
⚠️ 豁免**只覆盖冲刺**：其余单位 / 其余状态下的"禁移"一个字没改
（探针对照组：一个**没在冲刺**的扇子兵挨了同样一击后 `_kb_added` 仍为 0 ⇒ 走的仍是覆盖档）。
判定入口 `Unit3D.is_knockback_immobile()`；`Unit3D.is_knocked_back()`
（`_kb.length_squared() > 0.01`）仍然表示"正在被击退"，但**不再等于"禁移"**。
> 长矛兵 `击退数值 2` vs 三种老兵 `重量 1` ⇒ `1 < 2` 恒成立 ⇒ 它们仍然全程禁移；
> **骑士（重量 2）是第一个例外**（2026-09-18）：`2 < 2` 不成立，它被长矛捅到时**仍能走位**——
> 这是刻意的定位差，也是"能保持移动"那一支的第一个真实用例。

| 项 | 规则 |
| --- | --- |
| 移动 | **禁移档禁止**（重量 < 击退数值）—— `_tick_move()` 提前返回，并暂停卡住检测（否则"被推着后退"会被误判成卡住、白计 `_stuck_switches`）；**可移动档**照常走位，击退只叠加位移。⚠️ **2026-09-25 第八条：冲刺期间强制走"可移动档"**（判据 `_lance_active()`，见上面的例外） |
| 转向 | 照常 —— 仍持续面向目标 |
| 出手 | 照常 —— 射程判定放在击退门槛**之前**，被推着也能切入 `ATTACK` |
| 时长 | `_kb` 从等效初速衰减到 0.1 m/s 约 **0.39 s**（`KNOCKBACK_DECAY = 13`）；长矛兵的等效初速是 15.0 |

> ⚠️ **为什么必须在 `_think()` 之后再处理一次击退速度**：`_physics_process` 里
> `_think() → _tick_move()` 会写 `velocity`，如果只在它之前设击退速度，会被同帧覆盖。
> 改动前正是如此，所以**只有"站定攻击"的单位推得动**，MOVE 态的单位照常朝目标走——
> 这与"击退是位移效果"的设计自相矛盾。
> 实测：MOVE 态、目标在 −X 的长矛兵被 +X 击退 150 ms 后，x 由 0.000 → **+0.803**，
> `velocity = (1.666, 0, 0)` 为纯击退速度，不含 3.1 的自主移速。
>
> ⚠️ **2026-09-18 分档之后这两档的处理不同**（`unit3d.gd`）：
> **禁移档**是"整体覆盖 `velocity`"（与上面那段历史一致）；⚠️ **2026-09-25 第八条：冲刺期间不适用**
>（那一档改成"叠加"，见上面「禁移条件」里的例外）；
> **可移动档**是"把击退**叠加**在自主速度上"，所以必须用一个 `_kb_added` 记住上一帧叠进去的分量、
> 本帧先收回再叠——否则它会被 `_think()` 当成自主速度继承下来、**逐帧累积**
>（实测第一版就涨到 `_kb` 的 2.17 倍）。

**为什么是这组值**：长矛兵单次击退的推开距离 ≈ `(7.5 × 2 ÷ 1) / 13` ≈ **1.15 m**，
已经接近剑盾兵射程（1.8 m）的三分之二，被打中一次就要重新贴脸。
冷却 1000 ms ≈ 长矛兵的攻击间隔（1.0 s），即**每次命中都击退**。

### 5.1 击退动量转移（2026-09-18 新增）

| 常量名 | 含义 | 值 |
| --- | --- | --- |
| `KNOCKBACK_TRANSFER` | 被击退的单位撞到别人时，转移过去的速度比例 | **0.6** |

**规则**：被推着走、**或正在冲撞 / 跳跃**的单位在移动中撞到其他单位时，
把自己**当前速度**的 `KNOCKBACK_TRANSFER` 传给它（`Unit3D._transfer_motion_momentum()`）。
> ⚠️ **2026-09-19 扩展与对称化**：
> ① 适用面从"被击退"扩到 **击退 / 冲撞（骑士）/ 跳跃（狂战士）三者共用同一套**
>（`_physics_process` 里 `knocked` 与 `_charge_until_ms`/`_jump_until_ms` 两支都走它）；
> ② 只读 `get_slide_collision_count()` 是**不对称**的：A 先把 B 撞开、自己滑过去之后，
> 轮到 B 移动时前面已经空了 ⇒ 只有一方吃到动量。所以两支都**再补一次按距离判定**
>（`Unit3D._transfer_motion_to_contacts()`，半径用与冲撞结算同源的 `attack_reach()`），

> 把对手推远只会同时降低双方的输出时间（长矛兵自己也追不上）。

> 因为阵型被打散对远程更有利。

## 6. 朝向与坐标系

- Godot 默认右手系：+X 右、+Y 上、+Z 朝屏幕外。
- **选手的正面是自身的 −Z 方向**（`-global_transform.basis.z`）。
- 转向用 `atan2(-dir.x, -dir.z)` 算出 yaw，使 −Z 对准目标。
- **「横 / 纵」以双方朝向为参考系**（**不变量 I-36**，2026-09-18 立）：
  **"横" = 垂直于朝向**的方向（两队沿 X 对阵，所以横向 = 世界 **Z**）、
  **"纵" = 沿朝向、正面对进**的方向（= 世界 **X**）。
- **朝向不被击退改变**（2026-09-19 修 bug）：被推着走的那几帧里 `velocity` **就是**击退方向，旧代码
  让单位朝速度方向转身 ⇒ 盾牌正面、扇子兵的扇形攻击正面跟着乱转。现在 `_physics_process` 只在
  **未被击退**时按速度转身（`_state == MOVE and not knocked`）；朝向只由目标方向（`_tick_move()` /
  `_tick_attack()` 里的 `_face()`）决定——**被打得倒退时仍然面朝对手**。
  ⚠️ **参考系是朝向，不是屏幕**：相机默认沿 −Z 看向场地，因此一条"横排"在屏上必然呈现为
  "自远而近"的纵深——若拿屏幕当参考系，相机一换 `yaw` 就会得出相反的结论。
  本节也顺带记下调试脚本的 `横纵比` 口径：`span_z / span_x` = 横向跨度 / 纵向跨度
  （`debug_autoplay.gd#_report_spawn_layout`），与本约定一致。

### 6.1 出生朝向（`Arena.spawn_roster`）

出生时要让每队**面朝对面**。推导如下（yaw = 0 时 −Z 指向 −Z）：

| 队伍 | 出生位置 | 要朝的方向 | 需要的 yaw | −Z 转到的方向 |
| --- | --- | --- | --- | --- |
| 0（赤羽卫） | **−X（西）** | +X（对面） | **−π/2** | (+1, 0, 0) ✓ |
| 1（青锋卫） | **+X（东）** | −X（对面） | **+π/2** | (−1, 0, 0) ✓ |

> ⚠️ 这两个符号**极易写反**（历史上就反过一次：两队出生后背对背，见 `99_decisions.md`）。
> 改这里之后必须实测 `-basis.z` 与"指向对面的方向"的点积是否 ≈ **+1**。
> 2026-09-18 起两边由 `GameConfig.team_spawn_sign(team) * π/2` **推导**，不再各写一个常数。

> 这条约定是盾牌挡箭判定与出生朝向的共同基础，改动会让"正面"失效。

## 7. 盾牌挡箭（剑盾兵的专属机制）

### 7.1 判定式

```gdscript
if not unit.is_guard_up():   # 出手期间盾让开，直接不挡
    return false
to_source = -arrow.dir      # 从被击中者指向箭矢来向
to_source.y = 0
forward  = -unit.basis.z    # 剑盾兵正面
forward.y = 0
挡住  ⟺  forward.normalized().dot(to_source.normalized()) >= shield_arc_dot
```

| 常量名 | 含义 | 值 | 保护范围 |
| --- | --- | --- | --- |
| `shield_arc_dot` | 盾牌保护扇形的余弦阈值 | **−0.34** | 以正面为中心 **±110°**（约 220° 的扇形）——**只留背后 ±70° 的缺口** |

> ⚠️ **例外（2026-09-19 起为两个）**：**弩车的大型弩箭**与**投石车的石弹**都无法被挡下
> （`PROFILES["ballista"]["ignores_shield"]`、`PROFILES["catapult"]["ignores_shield"]`），
> `arrow.gd` 与模拟器都跳过上面的判定。理由与后果见 `#5.3`——弩车这条把"弩车 → 剑盾"从 23% 推到 **100%**，
> 也就是说**弩车目前没有克制手段**（只输给另一辆弩车）；投石车这条则是必需的：被判定"挡住"的石弹
> 只会钉在盾上、**不会落地炸开**，等于整发凭空消失。两者都是用户指定的方向，改动前请先确认。

> ⚠️ **2026-09-18 更正**：这里原写"正面约 ±70°（约 140° 的扇形）"，与阈值自相矛盾——
> `acos(−0.34) = 109.9°`，保护范围其实是 **±110°**，也就是说盾牌**不是**正面窄扇形，
> 而是"除了背后一个 ±70° 的锥形之外全挡"。（原注解很可能把"背后的缺口"当成了保护范围。）
> **实测**（剑盾兵朝 −Z，扫来箭方位角）：`0° / 60° / 90° / 100° / 109° 全挡`，
> `111° / 115° / 130° / 170° / 180° 不挡` —— 边界落在 **109°~111°** 之间，与算式一致 ✓。
> **阈值本身没有改**，改的只是这段注解。

### 7.1.1 出手期间盾失效（给弓手的窗口）

剑盾兵的盾牌会随攻击动作移开，因此**在出手中挡不住箭**：

| 项 | 定义 |

| 判定入口 | `Unit3D.is_guard_up()` —— 出手窗口内返回 `false`，`blocks_from()` 也随之返回 `false`。⚠️ **例外（2026-09-19）**：骑士的**盾牌猛击**不置 `_striking`，所以猛击期间 `is_guard_up()` 仍为 `true`、**照常挡箭**（用户对该技能的要求；它也是这个例外目前唯一的来源，见 `02_entities.md#2.3`） |
| ⚠️ **2026-09-27 第十二轮的第二个例外（肉鸽科技「高级格挡」）** | 买到该科技的**剑盾兵**在出手窗口内**也举盾**（`is_guard_up()` 对它恒为 `true`）—— 用户口径："允许剑盾兵**在攻击时**格挡小型远程投射物，**也能格挡子弹**"。⚠️ "也能格挡子弹"= 连 `ignores_shield` 那条道闸一起掀掉 ⇒ 原本"火枪子弹穿盾"这条口径**只对带该科技的剑盾兵失效**，其余单位一字未变。⚠️ **2026-10-01**：长矛兵的投矛也只有这一条科技挡得住。普通盾和月牙盾都让它过去 |
| ⚠️ **同一轮新增的第二个盾，2026-10-01 改口径** | 买到「This is SPARTA！」（原显示名「this is Spartan！」，id 仍是 `spartan`）的**长矛兵**手持**月牙盾**：站立时能挡小型投射物、**挡不了子弹**。⚠️ **攻击出手期间不能挡**（`is_guard_up()` 在 `_striking` 时返回 false，与剑盾兵的出手窗口同一段）。⚠️ 长矛兵面板里**没有 `shield_arc_dot`** ⇒ 举盾时按**全向**算（`blocks_from()` 里 `.get(..., -1.0)` 的兜底） |
| ⚠️ **种类闸门收在一个入口** | `Unit3D.can_block_projectile(is_small, ignores_shield, kind)`：`kind = "spear"` 时**只有**「高级格挡」返回真；其余种类上，高级格挡 = 小型（**含子弹**）；月牙盾 = 小型**且非子弹**；`has_shield()` 的普通盾 = 小型**且非子弹**（出手窗口另由 `blocks_from()` 管）。`arrow.gd#_resolve_segment()` 只负责问它 + 再问方向 |
| 影响范围 | 剑盾兵的出手窗口；另加买了「This is SPARTA！」的长矛兵（同一窗口里月牙盾失效）。「高级格挡」的剑盾兵是例外：出手时也挡 |
| 视觉表现 | 平时盾面**朝正前方**挡在身前；出手窗口内**旋转 + 横移**让到身侧——`GameConfig.UNIT_SHIELD_SWING`（额外 1.45 rad）+ `UNIT_SHIELD_OFFSET`（额外 −0.22 / −0.10 / +0.26 m） |

> ⚠️ **2026-09-18 修正（纯表现，判定未变）**：盾牌板的尺寸原先写成 `(0.10, 0.78, 0.58)`，
> **薄轴落在 X 上**，盾面因此朝左右而不是朝前——从正面只剩一条边，"盾在身前"从来没成立过。
> 现在薄轴改为 **Z**（`(0.58, 0.80, 0.10)`）并前移到身前；出手让位也从"只转 1.15 rad"改成"旋转 + 横移"。
> 实测两个姿态：平时法线 `(0, 0, −1)`（`|X| = 0.00`）、出手时法线 `(−0.99, 0, −0.12)`（`|X| = 0.99`）。
> **判定入口仍然是 `is_guard_up()` / `_striking`，与盾牌节点的 Transform 完全无关**——
> 表现再怎么动，挡不挡箭只看那一帧是否在出手窗口内。

**为什么加这一条**：盾牌原本是弓手的硬克制（实测剑盾兵 vs 短弓手 100%），
它此前把远程压得毫无办法（因此才有下面的"出手窗口"）。
加上"出手时失效"后箭矢挡下率从 72% 降到 **62%**，
> ⚠️ **2026-09-25 复采**：12 兵种混编、单次采样读到 **47.3%**（1779/3758）⇒
> **这个比例随阵容与样本波动**（62% 是 2026-09-17 的口径），**别把它当常数**；
> "盾牌是弓手的硬克制"这条**结论**不受影响（剑盾 → 短弓手 纯兵种仍 100%，见 `02_entities.md#8`）。
弓手在混编对局里的优势度从 17~38% 回到 **41~63%**（见 `03_rules.md#8`）。

### 7.2 规则

1. **只挡箭**，不挡近战（长矛/剑照常造成伤害）。
2. 挡下后：箭矢**插在盾上停留 1.2 s** 消失（**改挂到盾牌节点下** —— 剑盾兵 / 骑士是 `ShieldPivot`，月牙盾是 `CrescentShield` ⇒ 人走它跟着、出手时盾牌让位也跟着；见下条），~~剑盾兵闪白一次~~（⚠️ **2026-09-25 第七条已删除**，见下），发出 `Events.unit_was_blocked`。
   ⚠️ **2026-10-01**：肉鸽 / 沙盒调用 `Arena.stop_skirmish()` 收兵时，**还没消失的投射物立刻清掉**（含已经钉在盾上的）。否则 1.2 s 没走完，箭会跟着盾牌进下一回合。战斗进行中的 1.2 s 停留不变。
   ⚠️ **2026-09-25 第七条（用户两条："箭矢应停留在盾牌上而不是空中""兵种不应该有受伤特效"）**：
   ① **箭矢改挂盾牌节点**（此前只把它钉在**世界坐标**、而且位置是**射线打中单位胶囊**的那一点 ——
   既不在盾面上、人一走就吊在半空）；落点算法是"让**箭尖**落在盾面"，**不是**摆箭的原点
   （五个形态的原点都在杆中、箭头在 −Z，杆长 0.6~1.05 m ⇒ 摆原点会让箭有一大半穿到人身后）；
   ② **`on_shield_block()` 里的白闪已删除** —— 它原先和"挨打"共用同一个 `_flash`，所以**挡下 = 看起来被打了**。
   ⇒ 现在"挡下"只有 `Events.unit_was_blocked`（它另有两个与受伤无关的用途：`Arena` 的僵持计时、
   `06_audio.md` 的 `combat_shield_block`），**没有任何受伤反馈**。
3. 判定顺序：射线命中后**先查盾牌**，再查普通命中。
4. 参与判定的是：`has_shield = true` 的兵种（剑盾兵、骑士），以及买了「This is SPARTA！」的长矛兵（月牙盾，PROFILE 里 `has_shield` 仍是 false）。

### 7.3 为什么给这么宽的扇形

`−0.34` 对应约 **110° 半角**（见 §7.1 的更正）。窄扇形（如 60°）在快速转向的乱战里几乎永远挡不住，
会让"盾能挡弓箭"这条用户需求在实际观感上失效。

> ⚠️ **2026-09-26 第五块补记**：本项目现在有**两套互不相干**的"盾"—— 本节这一套是**剑盾兵的装备**
>（跟着人走、看朝向的扇形、`has_shield` / `blocks_from()`），另一套是**肉鸽的魔法盾**
>（场上的一个**世界空间圆**、不看朝向、没有碰撞体、谁都能走过去），判定在 `Arrow._magic_shield_crossing()`，
> 见 §8.1 的补记与 `09_roguelike.md#11.4`。⚠️ 读代码时别把两者混起来：`has_shield` 说的是**前者**。

### 8.1 线段查询与友军穿透（`arrow.gd#_resolve_segment`）

每帧对"上一帧位置 → 本帧位置"做**逐段查询**（最多 8 段）：

| 撞到的东西 | 处理 |
| --- | --- |
| 发射者自己 | 排除，不参与 |
| **友军** | 加入排除列表，从命中点继续往前查——**穿过，不消耗、不阻挡** |
| **已阵亡单位** | 同上，穿过 |
| **敌人 + 正面盾牌** | `blocked`：**插在盾上**（剑盾兵 / 骑士挂 `ShieldPivot`，月牙盾挂 `CrescentShield`）1.2 s，~~闪白~~（⚠️ 2026-09-25 第七条已删），发 `Events.unit_was_blocked`。⚠️ **2026-10-01**：`stop_skirmish()` 会提前清掉还钉着的箭，不带进下一回合 |
| **会偏折的敌人**（**只有**武士大师） | `deflected`：**方向取反、速度不变、归属改成它那一队**继续飞（2026-09-25，见 §5.3 的"高级偏折"行）。⚠️ **排在盾牌判定之前**，且**不看** `ignores_shield`；已被偏折过的那一发不再被偏折。⚠️ 闸门在 `Unit3D.try_deflect()` 里（**非大师一律返回 false**）—— 2026-09-25 修过一次"人人会偏折"的 bug |
| **敌人** | `hit`：结算伤害；⚠️ **2026-09-25 起若这一发还有 `pierce` 额度**（火枪子弹 = 1）⇒ **不收箭**：把被打中的单位加进 `_pierced`（**永久**排除出后续所有射线查询），弹体推到命中点前方 0.05 m 继续飞；额度扣到 0 才 `_expire()` |
| 地面 / 墙体 | `world`：插在原地 1.2 s 后消失 |

> 早期版本对友军只"跳过一段"就停，导致一排短弓手互相挡枪、整队零伤害（bug 2b）。
> 现在友军会被逐个跳过，箭最终会打到有射界的敌人。**这是"箭能穿过友军"的唯一理由**。

> ⚠️ **2026-09-26 第五块补记：魔法盾走的是另一条路 —— 不在上面那张表里。**
> 肉鸽的**魔法盾**是"半径 14 m 的圆、**没有碰撞体积**"（用户口径）⇒ 物理射线**永远查不到它**：
> 判定写在 `Arrow._magic_shield_crossing()`，位置在 `_resolve_segment()` **之前**，
> 用**线段与球面求交**（`_segment_sphere_entry()`）判"这一帧的位移有没有跨过圆边界"。
> 四条口径：① **方向无关** —— 从外打进来、从圆里打出去**都算跨过**（用户："若敌方远程在圆圈内发动攻击，
> 攻击也无法穿过魔法盾的边"）；② **不看 `ignores_shield`** —— 火枪子弹（能穿剑盾兵的盾）照样被挡
>（用户："火枪无法穿透"），它与武士大师的高级偏折**互不影响**（那条看 `is_small_projectile()`，另一条通路）；

>（投射物**从不直接改玩法数据**：盾的血量由肉鸽侧每帧读走并结算）。
> 挡弹物的登记表 `Arena.arrow_blockers` 存的是**值**（编号 / 圆心 / 半径 / 归属队），由肉鸽侧每次增删道具时
> **整体重写**，`arena.settle()` 一并清空。完整规则见 `09_roguelike.md#11.4`；
> ⚠️ 它与 §7 的「剑盾兵盾牌挡箭」是**两套完全独立**的判定，同一个兵种身上不会同时有这两样。

## 10. 调参流程

1. 只改**一个**参数。
2. 跑 `debug_autoplay`，记录平均比赛时长与平局率。
3. 目标区间：平均 25–60 s，平局率 < 20%，无 90 s 超时堆积。
4. 观感回归：起跳不需要，重点看**盾牌挡箭是否可见**、**击退是否看得见位移**。
5. 数值稳定后同步回本表与 `config.gd`。

> ✅ **2026-09-18：倍率取消 + 长矛兵伤害上调之后，第 3 条目标达标。**
> 两个倍率都改成 1.0 后击杀刀数约 2~3 倍（剑盾兵 135 HP 挨 51 → **3 刀**；270 HP 挨 34 → **8 刀**）；
> 随后长矛兵伤害 34 → **51**，又把"长矛兵 → 剑盾兵"从 43~50% 拉回 **85~95%**（见 `#5`）。
> **最终 4 次采样**：平均时长 **24.5 ~ 30.5 s**、**平局率 0%**（分胜负 20/20 × 16 个轮次槽），
> 实机 `debug_autoplay` 全部 `wipe` —— **无 90 s 超时堆积，无需改 `MATCH_LIMIT_MS`**。
> 改动前是 18~24 s（偏短），所以 25–60 s 这个区间是这次**首次真正达标**。
> ⚠️ 仍需留意的是"长矛兵 → 剑盾兵"**贴近 90% 上限**（均值 89%，单次到过 95%）——
> 若要回调，按 `#5` 的结论**改伤害**，**不要**把倍率加回来（那等于撤销 I-23 / I-24）。
