## 2. 一局的骨架

| 项 | 值 | 出处 |
| --- | --- | --- |
| 回合数 | **10** | `GameConfig.ROGUELIKE_ROUND_COUNT` |
| 每回合收入 | 第 1 回合 **25**、此后每回合 **+10**（`收入 = 25 + 10 × (回合 − 1)`）⇒ 序列 **25 / 35 / … / 115**，十轮合计 **700**。⚠️ **2026-10-01** 递增由 **+5** 改为 **+10**。⚠️ **2026-10-16** 第 1 回合由 **20** 改为 **25**（旧序列 20 / 30 / … / 110、合计 650 作废；更早的 20…65、合计 425 仍作废） | `ROGUELIKE_SUPPLY_START` / `ROGUELIKE_SUPPLY_STEP` / `roguelike_supply_income()` |
| 基础血量 | **200**（开局满血） | `ROGUELIKE_HP_MAX` |
| 失败 | **血量 ≤ 0** ⇒ 当场结束 | 用户口径 |
| 通关 | **打满 10 回合** | 同上 |

⚠️ **收入是"回合开始时先发到账"**（`_enter_prepare()` 里 `supply += income`），不是"打完之后结算"。
⚠️ **2026-10-16**：这一笔 = `roguelike_supply_income(回合)` **+** 已经记下的援助收入（`aid_income_bonus`）。补给专家、超级补给专家、成本控制专家在**选中的那一回合立刻再发一次**，同时把同一笔记进 `aid_income_bonus`，所以之后每个准备阶段还会再加，选中的那一回合不会加两次。统御核心的 +5 在 `RoguelikeAid.on_prepare()` 里另加，只在这队还在的准备阶段发，装备的那一回合已经过了这一步，第一笔从下一回合开始。
⚠️ **补给会被买兵 / 解锁扣掉**（见 §5）；基础收入仍只在回合开始时到账。放弃援助的 +5、战斗中打掉敌方指挥所的 +10，是另外两笔，见 §13。
⚠️ **2026-10-22**：收入到账、援助摆出来之后的这一刻会记在内存里。暂停菜单上的「保存并退出」写的是它，不是后来的购买或战斗。⚠️ **2026-10-23** 难度还没选时不记这一下；第 1 回合要等选完难度、敌人刷出来才记。见 §14。
⚠️ **血量下限夹在 0**（`maxi(hp - loss, 0)`）—— 浮层上不会出现负数。

## 3. 相位状态机（`Roguelike.Phase`）

| 相位 | 进入时机 | 这一相位做什么 | 怎么离开 |
| --- | --- | --- | --- |
| `PREPARE` | `begin()` / `next_round()` | **先把本回合的收入打进补给**，然后等玩家花钱 / 布阵（界面上的「开始战斗」）。⚠️ **2026-10-16** 第 2 回合起，这一相位末尾还要先选一条援助或放弃（§13）。没选完时「开始战斗」按下去没有用 | 按「开始战斗」⇒ `FIGHTING` |
| `FIGHTING` | `start_battle()` | 敌我交战。敌方作战单位没了 = 守住。我方作战单位没了 = 没打退，扣还活着的敌方权重。指挥所两边都不算 | 结算完成（或手动「结束回合」）⇒ `ROUND_RESULT` |
| `ROUND_RESULT` | `_settle_round()` | 显示本回合结果（扣了多少血 / 还剩多少） | 按「下一回合」⇒ `next_round()` |
| `GAME_OVER` | `_finish()` | 通关或失败，界面浮层接手（按钮变「重新开始」） | 按「重新开始」⇒ `restart_game()` |

- 相位串（`phase_name()`）：`"prepare"` / `"fighting"` / `"round_result"` / `"over"`。
- ⚠️ **`FIGHTING` 与另外两个模式的同名成员逐字一致**（`Game.Phase.FIGHTING` / `Sandbox.Phase.FIGHTING`）——
  2026-09-26 用户裁决：原先写的是 `BATTLE` / `"battle"`，与 `08_naming.md#1.4`「同一概念全局同名」相抵 ⇒ **改代码统一**（见该文件本批审计）。
- ⚠️ **"初始四选一"不是第五个相位**：它是 `PREPARE` 里的一道门（判据 `starter_chosen`；界面在它上面盖一层
  挡屏浮层）⇒ `Phase` 仍是**四个成员**、`phase_name()` 的四个串一个没变（口径见 §5.3）。
- ⚠️ **2026-10-23 「难度」也不是新相位**：它是同一道 `PREPARE` 里、起手四选一之前的另一道门（判据 `difficulty_chosen`）。没选完不刷第 1 回合的敌人，「开始战斗」按下去没有用。口径见 §12。
- ⚠️ **四个相位都能唤出暂停菜单**（与沙盒"任何相位都能唤出"同一口径；恒真的那一位在界面侧：`RoguelikeHud.pause_allowed()`）。
- ⚠️ **2026-10-18**：`start_battle()` 在 `on_fight_phase()` 之后打开操控闸门，**只限我方（team 0）**。回合结束、回到准备、人死了，或被策反离开 0 队，都会退出。操作见 `05_ui_hud.md#14`。敌方单位不能选。
- 状态跳变只通过 `_change_state()` 发本模式**自己的**信号 **`phase_changed(phase: String)`** ——
  它与 `Sandbox.phase_changed` 同名同义，**不上 `Events` 总线**。

## 4. 回合结算：扣血怎么算

| 结算那一刻 | 结果 |
| --- | --- |
| **敌方作战单位数 = 0** | "本回合守住了" ⇒ 扣血 **0**。同一帧我方也没了，仍走这一行 |
| 敌方还活着，**我方作战单位先没了** | 与「没打退」同一笔：扣血 = 下面那一行（2026-10-02） |
| 还有敌方作战单位活着（含手动结束） | 扣血 = **敌方存活兵种的 `weight` 之和**（`Roguelike.enemy_weight()`） |

- ⚠️ **2026-09-26 第三块修订："作战单位"= 1 队里除"建筑"以外的存活单位**（判据 `GameConfig.is_roguelike_only()`，
  目前只有指挥所）。原因是指挥所**每方常驻两座、权重 999** ⇒ 若沿用"存活数 = 0"，
  **回合永远结算不了**；同理那两个 999 权重也会让"没打退敌人"的扣血爆表 ⇒ `enemy_weight()` 同样排除它们。

- ⚠️ 用的是 `PROFILES[*]["weight"]`（配平用的占位成本），**不是 `mass`** —— 不变量 I-26 说过这两件事别混。
- ⚠️ 扣血后 `hp ≤ 0` ⇒ 当场进 `GAME_OVER`（`summary.reached_end = false`）；否则停在 `ROUND_RESULT` 等玩家点「下一回合」。
- ⚠️ **玩家固定是 0 队（赤羽卫，出生在 −X = 西）**、敌人是 1 队 —— 与不变量 I-35 的既有约定同源，
  不另开一套"谁是敌人"的约定（判据 `Roguelike._enemy_team()`）。
- ⚠️ **手动结束**（暂停菜单的「结束回合」）走 `Roguelike.end_round()`，与"敌方全灭"落到**同一个 `_settle_round()`**；
  它**自己解除暂停**（`PauseMenu` 不补第二次 `resume_match()` —— 同 `Game` / `Sandbox` 的分工）。
- ⚠️ **重开一局**走 `restart_game()`（与 `Game.restart_game()` 同名同义）：`arena.settle()` + 回到第 1 回合、补给 **25**（2026-10-16 起；此前这一句写 20）、满血。援助账一并清掉。

### 6.6 单位等级 / 经验 / 升级（2026-09-27 第四轮新增；**第五轮修了经验基数的 bug**）

> 用户口径（原文）："在肉鸽模式新增单位的等级，**一队兵种的等级保持相同，最高9级**。等级每增加1，
> 攻击和血量就增加一倍"；"（1）满经验：**队内单位每击杀一个敌方单位，这队单位就能获得所杀单位对应权重的经验**。
> **基础升级的经验为这队兵的总权重，等级每上升1就额外需要一倍的经验**，同理被击杀时额外给击杀者一倍的经验
> （如一队剑盾兵共10权重，则需要击杀共10权重的单位来升级，击杀1级矛兵获得1经验，击杀5级长矛兵给予5经验）。
> （2）：满经验时可以在**步兵阶段**选中单位进行升级，**升级价格为该队兵总权重的一半**
> （即在数值上可以看作与该队兵种解锁价格相同）。注：**兵种经验条一旦满了就不会再获得经验**，
> 只有升级后经验条空余了才能再次获得经验。"
> ⚠️ 同轮澄清（**这条推翻了我最初的 2^(L−1) 读法**）："**倍率 = L**，2 级 2 倍、9 级 9 倍" ⇒ 是**线性**的；
> 并给出乘区规则："百分比加成在同一乘区（+20% +20% ⇒ +40%），**倍率均为独立乘区**（+20%、×2、×3 ⇒ 1.2×2×3=7.2）"。
> ⚠️ **第五轮用户点名修的 bug**："一队兵升级所需经验是这一队兵的**总权重**，不是**单个兵**的权重" ——
> 上面那句原文里的"这队兵的总权重"我第一版实现成了单个兵的权重（见 §8.6 第 58 条与 `99_decisions.md`）。
> ⚠️ **2026-10-03** 推翻上面那句「等级每上升 1 就额外需要一倍」：第一级仍是一队总权重，之后每一级在这个基数上加 50%，不是 L 倍，也不是每一级再乘 1.5。见下表。

| 项 | 口径 |
| --- | --- |
| 等级住在哪 | **队上**（`squads[i]["level"]`，1..`ROGUELIKE_LEVEL_MAX`=9）；单位只是被动同步（`Unit3D.set_level()`）。⚠️ "一队同级"由生成路径保证：**初次布阵 / 复活补位 / 买兵全走 `_spawn_one_squad_unit()`**，它先设等级再发防御加成 |
| 倍率怎么算 | **`倍率 = L`**（`Unit3D.level_mult()`）且是**独立乘区**：血量 `(原始血 + 加法池) × L`、伤害 `面板 × 队伍倍率 × L`（落点见 `02_entities.md#2.12`）⇒ 2 级 = 2 倍、9 级 = 9 倍。⚠️ **与百分比加成（防御指令那种）互不干扰**：那类在"加法池"里相加，等级在外面乘 |
| 经验怎么来 | **击杀**：击杀者所在的那一队拿 `被杀单位的权重 × 它的等级` 点经验（用户例子：1 级矛兵 1 点、**1 级沙虫 25 点、3 级沙虫 75 点**）。⚠️ 实现靠 `Unit3D.killer()`（击杀归因，**没有新信号**）；⚠️ 陷阱 / 圈外内伤**无来源** ⇒ 不发经验（要改得先给陷阱记归属队）。⚠️ **2026-10-03**：心灵腐化师**不靠击杀**。策反一名单位时，总额仍是那名单位的权重 × 等级，按这一轮一起叠腐化的人数分摊，每一份向上取整，进各自所在的队。同一人反复照射只算一个。停照清零后，下一次重新计人。⚠️ **2026-10-16** 变种可以让这一队击杀不得经验，或把得到的经验再乘倍数。辅助扇子兵那种「每打中若干次 +1 队经验」走攻击计数，不走击杀 |
| 经验条 | 每队一个 `xp`。**升到下一级 = 一队总权重 × (1 + 0.5 × (当前等级 − 1))**（`GameConfig.roguelike_squad_xp_cost()`）。总权重 10 ⇒ **10 / 15 / 20 / 25**。出现半数时向上取整（总权重 15 的 2→3 是 **23**）。⚠️ **"一队总权重" = 编制数 × 单价权重**（= 买这一队要花的补给）。⚠️ **2026-09-27** 曾把基数误乘成单个兵的权重，已改回总权重。⚠️ **2026-10-03** 由「L × 总权重」改成上面这一条。⚠️ **满了就不再累积** |
| 升级动作 | **只在准备阶段**。选中该队：价 = **该队兵种的解锁价**（`GameConfig.roguelike_unlock_cost()`，= ⌊一队总权重 ÷ 2⌋）**加上这一兵种变种的 `upgrade_delta`，下限 0**（`upgrade_price_of()`）。⚠️ **2026-10-16** 这一队装备了「究极模块」时，升级按钮的价是 **0**（`upgrade_price()`）；精英招募加在招募价上的那一截仍用 `upgrade_price_of()`，不因为究极模块变成 0。升完：**等级 +1、经验清零**、这一队场上活着的兵全部 `set_level()`。⚠️ **2026-10-03** 旁边另有「全部升级」：这个兵种里现在付得起的队各升一级，一次只存一份撤销快照。能升的队，队形中心上方有一枚标记（见 `05_ui_hud.md#13`） |
| 满级 | 9 级封顶：`squad_xp_cost()` 返回 0 ⇒ 不再攒经验、面板写"已满级"、升级按钮灰掉 |
| 敌方也有等级 | ⚠️ **2026-10-04** 第 1～2 回合整波 **1 级**。第 3 回合起按出生顺序从**队尾**抬，不是整波一起跳。第 10 回合整波 **4 级**。一队仍然同级，写进账本并落到每个兵上（面板显示"等级 N 级（攻 / 血 ×N）"）。算法和各回合人数见 §12。测试敌人仍走 `_spawn_foe_squad(..., level)`。旋钮 `ROGUELIKE_TEST_ENEMY_LEVEL` 还在，回合流程不用。⚠️ 敌方**不升级**（它没有经验账） |
| 界面上读到的 | `squad_stats()` / `foe_stats()` 多出 `level` / `level_max` / `xp` / `xp_cost` / `upgrade_price` / `can_upgrade` / `upgrade_reason` / `upgrade_all_count` / `upgrade_all_price`（`05_ui_hud.md#13`） |

### 6.7 撤销（2026-09-27 第四轮新增）

> 用户口径（原文）："新增'撤销'按钮，能够**撤销本回合的上一次操作（只能是本回合）**（操作包括：买兵，升级兵，
> 移动兵，指挥所买增益，买陷阱魔法盾、放置信标等），快捷键'**ctrl**'+'**z**'，撤销时在**屏幕中央**显示一行字
> 显示撤销了什么操作。"；同轮选定实现方式 = **快照式整体回滚、可连撤多步**。

| 项 | 口径 |
| --- | --- |
| 实现 | **快照栈**（`_undo_stack`，LIFO、上限 40）：每个"会改本回合部署状态"的操作**之前** `_push_undo(label)` 存一份；`undo_last()` 弹出并整体回滚。⚠️ 好处是**一次实现覆盖用户列的全部操作**，不必为每种操作各写一个反向操作（那必然漏） |
| 快照装什么 | 补给 / 紧急补给欠账 / **队伍列表（含等级与经验、锚点、旋转、可动回合、编制、成本控制标记、装备的模块和装备回合）** / 已解锁池 / 两类增益 / 本回合两个计数 / 信标拥有权 / **全部道具**（含陷阱触发态、魔法盾血量、信标的**路线点**）/ **援助的经济、四选一、变种、已拿过的专家和援助卡**。⚠️ 只装"数字 / 字符串 / 数组 / 字典"，**不含活对象引用**。⚠️ **2026-10-16** 便携魔法盾（kind `"aid_ward"`）不进快照，开战再造。援助留下的油、酸、烟、火区随援助账回滚 |
| 回滚怎么做 | **清场重建**：撤掉我方队伍单位与所有道具 → 写回数值 → 按快照**重新生成**（与买兵 / 放道具**同一条生成路径**）+ **重算占格账**（指挥所先占、再逐队占）⇒ 等级 / 加成 / 落位 / 拥有权都不会漏。⚠️ **指挥所与敌人不动**（它们不在快照里：指挥所只在回合开始重建，敌人不由玩家操作） |
| 哪些操作会存快照 | **9 处**：买兵 / 解锁兵种 / 升级 / 拖动换位 / 买持续增益 / 买单回合增益 / 买信标 / 放道具（含信标重放）/ **画完信标路线**。⚠️ **2026-10-03**：「全部升级」算在升级这一处里，一次点按只存一份快照。⚠️ **2026-10-16** 再加：接受援助、放弃援助、放置援助卡、训练、再部署、高效遣返、装备战术模块、援助给的移动信标。都在改动之前存 |
| 何时能用 | **只在准备阶段**（那些操作本来就只发生在这一档）；⚠️ 回合开始时**栈清空**（用户："只能是本回合"）⇒ 战斗中按 Ctrl+Z 不会有任何事发生 |
| 界面 | 底栏右栏一颗「**撤销**」按钮（写着"还能撤几步"，空栈 / 非准备阶段自动灰掉）+ **屏幕中央一行字** `UndoToastLabel`（"撤销：<操作名>"，`UNDO_NOTE_MS` = 2.6 s 后自己消失，纯表现）。⚠️ 玩法侧 `undo_note()` 是**唯一**的时间源（界面不自己算时间，I-13） |
| 快捷键 | `Ctrl+Z`（`_unhandled_input` 里判 `ctrl + Z`；⚠️ 忽略按住重复 `echo` ⇒ 按住不放不会连撤） |
