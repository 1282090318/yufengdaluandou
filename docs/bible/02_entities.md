### 1.1 依赖方向

```
main ──> game ──> arena ──> unit ──> arrow
  │        │        │         │
  └────> hud      camera_rig  └──> unit_factory
                     │
        events / game_config（Autoload，任何层都可用）
```

- 玩法层**不认识** UI 与相机：它们只订阅 `Events` 的信号。
- `hud` 只读 `Game` 的公开状态、只调 `Game` 的公开方法，不直接改数据。
- ⚠️ **2026-09-26 补记（肉鸽那一支）**：`roguelike` 挂在 `main` 下、**只读 `Arena` 的公开接口**并把"队伍级修正"
  与"圆形挡弹物"写进 `Arena` 的**场地字段**（`team_damage_buff` / `arrow_blockers` 等 —— 单位每帧自己读）；
  `roguelike_hud` 只读 `Roguelike` 的公开状态、只调它的公开方法（**包括"取消选中"这类写操作也走公开方法**，
  见 `05_ui_hud.md#13` 的 R-07）。⚠️ **反向依赖不存在**：`arrow.gd` 认的是 `Arena.arrow_blockers`（值），
  不认 `roguelike.gd`。
- **`hud` 的按钮节点只构建一次**：`Game` 以 10 Hz 发 `phase_changed`，若每次刷新都重建卡片，
  按钮会在"按下"与"抬起"之间被销毁，点击永远不会生效（bug 2c）。
  现在只更新 `text` / `disabled` / 颜色，不重建节点。
- ⚠️ **2026-09-25：`hud` 不再是"全部界面"** —— 现在有**三套并列的界面**（`hud` 竞猜 / `sandbox_hud` 沙盒 /
  **`roguelike_hud` 肉鸽，2026-09-26 新增**），
  共用件抽在 `ui/pause_menu.gd`（暂停菜单）与 `ui/ui_style.gd`（外观）里，装配由 `main` 按模式分岔。
- ⚠️ **`game` / `sandbox` / `roguelike` 是并列的三种模式**：都由 `main` 装配、**互不认识**；后两者同样往下用
  `arena` / `camera_rig`，但它**不调用 `Arena.start_match()`**（改用 `start_skirmish()` / `stop_skirmish()`）
  ⇒ 兴奋圈 / 90 s 时限 / 僵持判平 / 平局判定在沙盒里**整体失效**（见 `03_rules.md#10`）。
- ⚠️ **暂停的公共件**在 `core/match_pause.gd`（纯静态工具：`pause_tree()` / `resume_tree()` /
  `shift_deadlines()`）：**三个模式都只往下依赖它**，算法只有一处（肉鸽的记账字段同样叫 `_pause_from_ms`）。

## 2. 选手（`unit`）

### 2.1 职责与边界

- **负责**：找最近敌人、走位、攻击、受击、死亡演出、血条。
- **不负责**：胜负判定（→ `arena`）、点数结算（→ `game`）、镜头（→ `camera_rig`）。
- **索敌**：**只打距离最近的敌人**，每物理帧重算（前后各锁一次），目标改变即重置攻击节奏。
  规则与历史见 `04_physics.md#3.4`。
- **生命周期**：每轮 `arena.spawn_roster()` 生成；阵亡后 0.7 s 淡出并 `queue_free`；不做对象池。
  ⚠️ **2026-09-19 新增「尸体滑行」**：若阵亡瞬间正处于**被击退**状态，尸体先是**实体**——保留单位层
  碰撞与击退速度，能挡活人、也能被继续推，最长 **0.8 s**（或击退速度衰减到 **1 m/s** 以下）才交回
  普通阵亡演出。这是弩车「传递伤害」能落地的前提：一发 400 秒杀时，被秒的人以前会立刻失去碰撞，
  根本飞不到同队单位身上（常量 `CORPSE_SLIDE_MAX_MS` / `CORPSE_SLIDE_MIN_SPEED`）。
- **出生朝向**：由 `Arena.spawn_roster` 按队伍设定，必须**面朝对面**（推导见 `04_physics.md#6.1`）。
  开赛后 `Unit3D._face()` 会持续把 −Z 对准自己的目标。
- **对外信号**：通过 `Events` 发出 `unit_spawned` / `unit_was_hit` / `unit_was_blocked` / `unit_died`。

### 2.2 状态机

| 状态 | 进入条件 | 允许的动作 | 退出条件 |
| --- | --- | --- | --- |
| `IDLE` | 无目标 | 原地微浮动，寻找目标 | 找到目标 → `MOVE` |
| `MOVE` | 有目标但在射程外 | 朝目标移动、转向 | 进入射程 → `ATTACK`；目标消失 → `IDLE` |
| `ATTACK` | 目标在射程内 | 面向目标，按**攻击冷却**出手（冷却 = 1 ÷ 攻速；命中帧 = 冷却到点的那一帧，动画第 0 帧 = 命中帧 − 前摇 ⇒ **命中与动画顶点同帧**，见 `04_physics.md#3.5`） | 目标出射程/死亡 → `MOVE`；自身死亡 → `DEAD` |
| `DEAD` | `hp <= 0` | 倒地演出 0.7 s 后销毁（⚠️ 被击退致死时先**滑行**至多 0.8 s，见 §1 生命周期） | 演出结束 → 销毁 |

转换优先级：**死亡 > 目标失效 > 进/出射程**。

### 2.3 技能（2026-09-18 新增机制）

**规则**：技能写在 `GameConfig.PROFILES[*]["skill"]` 里，由 AI 在**满足触发条件时自动释放**，
释放后进入**冷却**，冷却结束之前不会再次释放。技能**不是属性**（不进 §3 那张表），
而是像 `"thrust"` / `"shield_arc_dot"` 那样的行为标记。
⚠️ **2026-09-19 起有唯一一个"无冷却"技能**（火焰拳·**炎爆**）：它不看 `_skill_cd_until_ms`，
节奏完全由技能自己的流程决定（蓄力 1 s + 冲刺 + 延迟 0.5 s + 自晕 1 s ≈ **2.7 s 一轮**），
所以下表"冷却"列写的是**无冷却**。

| 项 | 约定 |
| --- | --- |
| 触发 | 每物理帧检查一次；条件不满足就不放，**满足且冷却已结束**才放 |
| 冷却 | 用 `Time.get_ticks_msec()` 记绝对时刻（不变量 I-13）；数值以 `_CD_MS` 结尾，住在 `GameConfig`（I-15） |
| 时机 | 单位**不在出手动作中**（`not _striking`）才允许发动 |
| 状态机 | **不新增状态**：§2.2 的五个状态不变，技能表现为"临时覆盖速度 / 追加一次结算" |
| 表现 | 复用既有出手动画与位移，不做技能专用动画 |

> ⚠️ **2026-10-18 操控**（沙盒与生存的战斗，操作见 `05_ui_hud.md#14`，位移见 `04_physics.md#3.6`）：接管之后 AI 不再自动放技能。数字键 `1` 只放「只有一个主动技能」的那一个，方向取按下时的水平准星。骑士只放冲撞，盾牌猛击仍只由 AI 放。狂战士跳跃的水平距离改成 `UNIT_JUMP_RANGE × tech_jump_mult()`。火焰拳沿那个方向冲，撞到面前的人再炸。轻骑兵冲刺在飞行中改跟当前准星。沙虫不占这一颗键。武士大师、影袭、召唤、手雷按 `1` 不做事情。影袭仍是挨打才触发。石柱的召唤节拍照走。

### 2.4 眩晕（2026-09-19 新增的**附加状态**）

> ⚠️ 它**不是** §2.2 状态机里的第五个状态，而是与"击退窗口"同类的**附加状态**
> （`Unit3D._stun_until_ms`）：§2.2 的 `IDLE / MOVE / ATTACK / DEAD` 因此保持不变 ——
> 与 §2.3 的技能"不新增状态机状态"是同一条设计原则。
> ⚠️ **2026-09-25 起它有了一个兄弟状态「定身」（§2.6）**：两者对"能不能行动"完全一样，
> 唯一区别是**定身还免疫一切位移**。判"不能行动"请用 `is_incapacitated()`，别只问 `is_stunned()`。

| 项 | 口径 |
| --- | --- |
| 数值 | **持续时间**（用户："数值为持续时间"）。入口 `Unit3D.apply_stun(duration_ms)`；同时挨多次时**取较长的那一次**（不叠加、也不会被更短的一次刷短） |
| 效果 | **无法进行任何行动**：`_physics_process` 跳过 `_think()` ⇒ 不移动 / 不转向 / 不攻击 / 不放技能；状态拨回 `IDLE` ⇒ 自主速度按既有减速收干净 |
| 打断 | **进行中的技能全部被打断**（骑士冲撞 / 狂战士跳跃 / 火焰拳炎爆的蓄力与冲刺）。⚠️ 炎爆被打断时**不会爆炸**；⚠️ **三个技能都可能正在"穿队友"**（2026-09-19 第三条起，见 `04_physics.md#5.2`），被打断时己方队伍层**立刻**加回掩码（走 `_set_ally_ghost(false)` 这条"抢先还原"路径，不走技能正常结束时的延时还原）。⚠️ **2026-09-25 第五条：轻骑兵（矛）的冲刺是这条规则的唯一例外 —— 它被「暂停」而不是「打断」**（用户："轻骑兵的冲锋在被眩晕打断后能在眩晕结束时继续冲锋（眩晕持续期间不进行技能持续时间计时），直到 10s 为止"）：冲刺**不结束、不作废、不退额度**，只把截止时刻**往后推被晕掉的那一段**，晕完接着冲完剩下的时间（直接证据：总时长 = 10 s + 被晕的秒数）。⚠️ 所以 `_interrupt_skill()` 里**没有也不该有** `charge_lance` 分支 —— 计时补偿与穿透掩码的收放全在 `apply_stun()` / `_lance_tick()`。⚠️ 沿革：同日第四条曾把它做成"真打断 + 退还额度"，**第五条已推翻**（当时那句"只有它有额度这回事"随之作废） |
| **不拦**的东西 | 重力、**击退**（眩晕不免疫击退，与 `04_physics.md#5` 的"禁移"判定各管各的）、**伤害**（不免疫伤害，圈外内伤照常结算）与碰撞 |
| 判定 | `Unit3D.is_stunned()`（阵亡后恒为假）；计时一律 `Time.get_ticks_msec()`（不变量 I-13） |
| 表现 | 模型**原地摇晃**（脚本里的纯表现常量 `STUN_SWAY_ANGLE`）；不眩晕时该角度**显式归零**（阵亡倒地共用同一个 `_visual.rotation`） |
| 目前来源 | **三处**（前两处 2026-09-19，第三处 **2026-09-25 第五条**）：① **火焰拳的炎爆**（撞击 1 s / 爆炸 1 s / 自身 1 s）；② **沙虫浮出地面那一圈**（半径 **6 m**、**不分敌我**、1 s，见 §2.3 ⑧ —— ⚠️ 半径 2026-09-25 由 4 m 改为 6 m）；③ **投石车石弹的落点**（半径 **4 m** 内**所有敌方**、**直击与溅射不分档**、1 s = `UNIT_STONE_STUN_MS`，见 `04_physics.md#5.3` —— 用户："会对所有击中的敌人附加眩晕 1"）——⚠️ **三处都走同一个 `apply_stun()`，因此都吃同一条免疫闸门**（⚠️ 判据 **2026-09-25 第六条已改名**：`is_boss()` → `GameConfig.is_stun_immune()`，**boss ∪ 两台载具** ⇒ **投石车与弩车对这三处眩晕全部免疫**）。⚠️ ③ 是**第一个挂在投射物上的眩晕源**（前两处都是技能），也是**唯一会同时晕到一片人**的来源 |

### 2.5 兵种模型预热（2026-09-25 修 bug：第一次画某个兵种会**卡住一整帧**）

> 用户报的现象："沙盒模式偶尔会出现点击下兵后**过一会儿兵种才会在场上出现**（拖动也是）"。
> ⚠️ 根因**不在玩法**（兵是**当帧**就摆下的，探针实测过），而是**某个兵种的模型第一次被渲染时现编译着色器**：
> 整整卡住一帧（实测 **594 ms**；已经画过的兵种只要 **18 ms**）。
> ⚠️ **为什么"偶尔"**：开始界面的背景演示只用到 5 个兵种（剑盾 / 长矛 / 短弓 / 长弓 / 扇子），
> 剩下 7 个（骑士 / 投石车 / 弩车 / 狂战士 / 火焰拳 / 轻骑兵 / 沙虫）**从没被画过** ⇒
> 玩家在沙盒里第一次摆到哪一个，就在那一刻卡一下。

| 项 | 口径 |
| --- | --- |
| 何时做 | **打开游戏那一次**：`main.gd#_ready()` 里调 `main.gd#_prewarm_unit_models()`（`_prewarmed` 把关 —— 退回主菜单会重开开始界面，但不重做） |
| 做什么 | 临时建 `WarmupStage` + **19 个兵种各一个 `Unit3D`**（节点名 `Warmup_<序号>`，见 §7），**只用 0 队**（两队差别只是材质底色，着色器变体相同）；每个都调 `Unit3D.warmup_show_all_fx()` **连"透明 / 自发光"那几套特效件一起显示**，并冻掉 `set_process(false)` / `set_physics_process(false)`（不冻的话 `_update_flame_fx()` 当帧就把刚显示的件藏回去）、`collision_layer/mask = 0`（免得这几个临时兵挡住 / 推开背景演示兵）；**画满 3 帧**后连台子一起 `queue_free()`。⚠️ **2026-09-26 起 `warmup_show_all_fx()` 的名单里多了一个 `_fx_shadow_form`**（影魔影袭的贴地影子，出厂隐藏）—— 它同样是"不画一帧就不会编译"的那一类 |
| 为什么放在这一屏 | 开始界面**整屏是黑的**（黑幕要到背景预演冻住才渐亮）⇒ 这笔一次性卡顿、以及这几个临时单位，**都不会被看见**。⚠️ 着色器是**进程级**的 ⇒ 预热一次**三个模式**都不再付这笔钱 —— 竞猜模式原先是在黑幕里刷阵容，所以从没暴露过这个问题 |
| 实测 | 预热后单摆一个沙虫 **≤ 40 ms**、稳态 **≤ 15 ms**、>30 ms 的尖峰 **0 个**。⚠️ 代价 = **启动那一屏多一笔开销**（19 个兵种各画一帧，估 ≈1.0 s；一次性、全黑期间、玩家看不见） |
| 同类修法 | `arena.gd#_build_impact_dust_pool()`（落点扬尘的预建池，见 `04_physics.md#5.3`）—— 都是"**不要在运行期新建网格 + 材质 / 首次绘制现编译着色器**"这一类 |
| **同一种兵的网格只造一次**（2026-10-02） | `UnitFactory.build()` 按兵种留一份模板（用 0 队造）。之后摆的人复制节点、**共用网格**，材质各自一份（受击闪白不能串到别人身上）。1 队按 0 队的队伍色和盾上那一档提亮色换过去。弩车弦杆 `BowStringBar_*` 每帧改长度，**不共用**。第一种仍要现造一次；预热那一次会把模板留下 |

> 新兵种自动被画到。反过来，**任何"只在运行时第一次出现的网格 / 材质组合"都要先想一遍这笔首帧开销**

### 2.6 定身（2026-09-25 新增的**附加状态**，与 §2.4 眩晕成对）

> 用户口径："新增效果：**定身**：与眩晕同样为**无法进行任何操作**，但与眩晕的区别为
> **被定身的单位无法被位移（包括击退）**。"
> ⚠️ 它同样**不是** §2.2 状态机里的状态（`Unit3D._root_until_ms`），与 §2.4 是**兄弟**：
> **"不能行动"那一半完全一样，唯一区别是"能不能被位移"**。

| 项 | 口径 |
| --- | --- |
| 数值 | **持续时间**。入口 `Unit3D.apply_root(duration_ms)`；同时挨多次**取较长者**（同眩晕，不叠加、不被更短的刷短） |
| 效果（与眩晕相同的部分） | **无法进行任何行动**：`_physics_process` 跳过 `_think()`、状态拨回 `IDLE`、武器收回静止姿态（`_animate_attack()` 断动画链）；进行中的技能走 `_interrupt_skill()` |
| 效果（**与眩晕唯一的区别**） | **一切外力位移都吃不上**：`_add_knockback()` 入口直接返回（击退 / 动量转移 / 被冲撞推开三条路都经由它），且本帧已经攒下的击退速度**就地清零**（`_kb = Vector3.ZERO`）。⚙️ 判据 `Unit3D.is_rooted()`。⚠️ **只挡位移**：伤害照常结算（定身**不免疫伤害**，与眩晕一致） |
| 判定 | `Unit3D.is_rooted()`（阵亡后恒为假）；"能不能行动"统一问 `is_incapacitated()` = **眩晕 ∪ 定身 ∪ 准备期**（2026-09-27 第七块加了第三项，见 §2.9）（`_think` 闸门、收武器、断动画链三处都用它）；计时一律 `Time.get_ticks_msec()`（I-13），进 `shift_deadlines()` 的属性扫描（暂停恢复自动补偿） |
| 与冲刺的关系 | 与眩晕**同一条"暂停"语义**：轻骑兵（矛）的冲刺被定身时**不作废、不退额度**，只把截止时刻往后推被定住的那一段（共用 `_pause_lance()`，见 §2.4 的"打断"行） |
| ⚠️ **与 boss / 载具免疫的关系** | **定身刻意无视 `GameConfig.is_stun_immune()`**（boss ∪ 载具那道闸门）—— 用户 2026-09-25 明确裁决"**定身无视 boss / 载具的免疫**"，因为拔刀斩的口径是"**包括 boss 单位**"。⇒ **沙虫、投石车、弩车都定得住**，而它们对眩晕仍然免疫（实机探针：同一只沙虫 `眩晕吃不上 / 定身吃得上`）。这是"整类免疫"的一条**成文例外**，**不要照抄到眩晕上**（见 `99_decisions.md` 同日条目） |
| 目前来源 | **一处**：**武士大师的拔刀斩**（沿途被穿过的敌方单位**定身 1 s**，含 boss；它自己也吃 1.5 s 自定身，见 §2.3）。⚠️ 自定身是**技能的一段**、直接写 `_root_until_ms`，**不走 `apply_root()`** —— 否则会经 `_interrupt_skill()` 把整段技能作废（这条踩过，记在 `99_decisions.md`） |
| 表现 | 与眩晕**共用"站定不动"这条读法**，但**不做**眩晕那种原地摇晃（`STUN_SWAY_ANGLE` 只跟 `is_stunned()`）—— 定身读起来是"被钉在原地" |

### 2.7 减速（2026-09-26 新增的**附加状态**，与 §2.4 眩晕 / §2.6 定身同族但**不挡行动**）

> 来源：肉鸽第五块的**陷阱**（用户："造成 200 点伤害并使移动速度降低 80%，持续 3s"）。⚠️ **2026-10-14**：现行伤害是 **500**。引号里是当时的原话。
> ⚠️ 它同样**不是** §2.2 状态机里的状态（`Unit3D._slow_until_ms` / `_slow_mult`），
> 但与眩晕、定身是**三件不同的事**：**减速照样能行动**（走位 / 出手 / 放技能一概不受影响），只是走得慢。

| 项 | 口径 |
| --- | --- |
| 数值 | 两个字段：**倍率**（0.20 = −80%）+ **持续时间**。入口 `Unit3D.apply_slow(mult, duration_ms)`；判定 `is_slowed()`、取值 `slow_factor()`（没被减速 = 1.0） |
| 落在哪 | 陷阱这一份先折成百分数（−80%），再和沉默的 −30%、沙暴的 −40% **加在同一个移速百分数池**里，由 `current_speed()` 乘一次 `max(1 + 百分数之和, 0)`。米每秒的加减在这之前。⚠️ **2026-10-02**：不再是先乘陷阱、再乘沉默 |
| 多次叠加 | 与眩晕"取较长者"同源、只是多一维：**截止时刻取较晚的**（更短的一次不缩短原来那次）+ **倍率取更慢的那个**（`minf`）。⚠️ 若这一次来的时候上一次已经过期，则**从干净的倍率起算**（不会被上一发的残留值拖住） |
| **不做什么** | **不进 `is_incapacitated()`**、不碰 `_interrupt_skill()`、不挡位移、不免疫伤害 —— 这四条都是它与眩晕 / 定身的区别（判"能不能行动"仍然只问 `is_incapacitated()`） |
| 计时 | `Time.get_ticks_msec()`（不变量 I-13）。⚠️ **字段名必须以 `_ms` 结尾且是整型** ⇒ 自动进 `shift_deadlines()` 的 `_*_ms` 属性扫描（暂停恢复的补偿不用另接）—— 改名会让暂停期间白流逝减速时间 |
| 目前来源 | **一处**：肉鸽的**陷阱爆炸**（半径 10 m 内所有敌方单位都吃 −80% / 3 s，见 `09_roguelike.md#11.3`）。⚠️ 它是**第一个"非技能、非状态机"的移速削减来源**；三个模式共用同一个 `Unit3D`，但别的模式里这个字段恒为 0（`slow_factor()` = 1.0 ⇒ 结果与改动前逐位相同） |
| 表现 | **无专属表现**（不摇晃、不变色）—— 与"眩晕摇晃 / 定身站定"刻意不同：减速是"还在动，只是慢"，靠走位本身读出来 |

### 2.8 移动信标路线（2026-09-26 第六块：肉鸽独有的"**沿路线平移**"指令）

> 来源：肉鸽的**移动信标**（用户口径与三条补充裁决见 `09_roguelike.md#11.5`）。
> ⚠️ 它**不是** §2.2 状态机里的状态、也**不是** §2.4 / §2.6 / §2.7 那种"附加状态"：
> 它不改状态机、不改基础移速、不进 `is_incapacitated()` —— 只是在 `_think()` 里**接管这一帧的走位**。

| 项 | 口径 |
| --- | --- |
| 挂在哪儿 | `Unit3D._beacon_points`（路线，信标 → P1 → P2）+ `_beacon_offset`（挂上那一刻自己到路线的**垂直偏移**）+ `_beacon_arc` / `_beacon_total`（已推进 / 全长的**弧长**，米）。⚠️ 2026-09-27 第七块把 `_beacon_s` **改名成 `_beacon_arc`**（单字母 `s` 读不出来），`_route_project()` 返回字典里的键也跟着从 `"s"` 改成 `"arc"` |
| 入口 | `Unit3D.set_beacon_route(points)` / `clear_beacon_route()` / `has_beacon_route()`；由 `Roguelike._capture_beacon_routes()` 在**开战那一刻**指派（回合开始时全部清掉）。⚠️ 第七块起**同一时刻还调 `set_facing(第一段方向)`** —— 被影响的单位**朝向 = 路线第一段**（用户口径），瞬时拧过去、不走平滑 |
| 怎么走 | 每帧沿路线推进 `current_speed() × delta` 的弧长，落点 = 路线上的点 + `_beacon_offset` ⇒ **整队保持队形沿折线平移**（用户裁决的移动方式） |
| 朝向 | **没在攻击 ⇒ 沿路线**（`_face(行进方向)`）；**攻击中 ⇒ 交给目标**（`_tick_attack()` 内部自己转）。⚠️ **2026-09-27 修 bug**（用户："在被移动信标影响移动的时候兵种也是能攻击的（不影响移动）"）：修前这一支**既调 `_tick_attack()`（朝向目标）、又在后面无条件 `_face(路线方向)`** ⇒ 两个朝向每帧打架、命中帧永远朝着行进方向，**看起来就是不攻击** |
| 插在 `_think()` 的哪儿 | **技能之后**（冲刺 / 跳跃 / 炎爆是更强的"整帧接管"，信标不顶掉它们）、**"没有目标就待机"之前**（没敌人也照走）；够得着就先按常规打一下（并把 `_state` 置成 `ATTACK`）、**再把速度改成沿路线的** ⇒ 用户要的"攻击时也会移动"（⚠️ 实测：接触距离内**边打边走**，敌方 300 → 220 血的同时 x 仍在推进） |
| 速度 | 夹到自己的 `current_speed()`（转弯处"该到的点 ÷ delta"会大于面板移速，不夹会在拐角弹射） |
| 结束 | 弧长走到全长 ⇒ `clear_beacon_route()` ⇒ 恢复自由移动（用户："移动到终点时开始自由移动"） |
| ⚠️ 与准备期的先后 | 第七块起：落在**对方底线那一段带子**里的单位开战时先吃 **5 s 准备期**（§2.9）⇒ 那 5 s 里 `_think()` **整段不跑** ⇒ **准备中的兵不会沿路线走**，等准备期过完才接管 |

### 2.9 准备期（2026-09-27 第七块新增的**附加状态**：布阵带的"落地启动时间"）

> 来源：肉鸽的**两条布阵带**（用户："我方单位每当部署到这个场地时需要 **5 s 准备时间**（5 s 后才能行动，
> 期间会被敌方攻击）……在这个区域部署后的**下一个回合开始则不需要启动时间**"，见 `09_roguelike.md#6.5`）。
> ⚠️ 它**不是** §2.2 状态机里的状态（`Unit3D._prep_until_ms`），但与眩晕 / 定身是**同一族的"不能行动"**、
> 与减速那种"照样能行动"正相反。

| 项 | 口径 |
| --- | --- |
| 数值 | 一个字段：**到期时刻**（绝对毫秒，I-13）。入口 `Unit3D.apply_prep(duration_ms)`；判定 `is_preparing()`（读起来像断言）。同时挨多次取**较长**者（与眩晕同源） |
| **能做什么 / 不能做什么** | **不能移动 / 不能转向 / 不能攻击 / 不放技能**（`is_incapacitated()` 里算数 ⇒ `_think()` 整段不跑、`_state` 拨回 IDLE）；**会被攻击**、**也会被击退与动量传递**（⚠️ 与「定身」正相反 —— 定身连位移都免疫，所以准备期**没有**进 `is_rooted()` 那条闸门；`_add_knockback()` 一行都没改） |
| 计时 | 只从**开战那一刻**起算（用户裁决：落子当下不计时）⇒ 施加入口只有一处：`Roguelike._capture_zone_prep()` 在 `start_battle()` 里按"位置 + 本回合进入"两个判据发 |
| **跨回合免启动** | 判据不是"在不在带子里"而是"**是不是本回合被放进去的**"：每个单位带一个 `zone_entered_round`（落位 / 挪位那一刻由 `Roguelike._mark_zone_entry()` 写），开战时只给 `== round_index` 的发准备期 ⇒ 上一回合就在里面、之后没挪过的兵**直接免启动**（用户那后半句）。复活的兵由生成函数新造 ⇒ 默认 `-1` |
| 暂停语义 | 字段名以 `_ms` 结尾且整型 ⇒ **自动进 `shift_deadlines()` 的属性扫描**（暂停恢复时把截止时刻整体后移）—— 改名会让暂停期间白流逝准备时间 |
| 目前来源 | **一处**：肉鸽的布阵带（`ROGUELIKE_ZONE_PREP_MS` = 5000）。别的模式里这个字段恒为 0、`is_preparing()` 恒为假 ⇒ 行为与改动前逐位相同 |
| 表现 | **无专属表现**（不摇晃、不变色）—— 与眩晕 / 定身一致：把它读出来的是"站着不动"本身 |

### 2.10 回合开始复位（`Unit3D.reset_to()`，2026-09-27 新增的**方法**，不是状态）

> 来源：肉鸽**回合开始要"整队按当初的布阵站好"**（用户："回合开始时兵种未回到原位"，
> 见 `09_roguelike.md#6.4` 的「回合开始恢复」）。
> ⚠️ 它**不是**状态机里的状态、也不发信号：**一次性**把单位"摆回某个位置 + 朝向"，
> 并把**这一场攒下来的瞬时状态**就地清掉 —— 与 `heal_to_full()`（只管血）分工互补。

| 项 | 口径 |
| --- | --- |
| 入口 | `Unit3D.reset_to(at: Vector3, facing: float)`（只在 `alive` 时生效）。⚠️ 高度一律取 `SPAWN_HEIGHT`（与 `Arena.spawn_unit()` 同一条口径），**y 交给重力落定** —— 免得"从空中掉下来的兵"被直接摆到地面而与地形穿插 |
| **清掉哪些**（= "这一场攒下来的"） | 速度 `velocity` / 击退 `_kb` / 状态机 `_state`（拨回 `IDLE`）/ 出手链 `_striking` / **进行中的技能**（`_interrupt_skill()`：冲刺 / 跳跃 / 炎爆 / 拔刀斩）/ **影子形态**（`_end_shadow()`）/ **潜地**（`_burrow = SURFACED` 并清 `_burrow_until_ms` / `_no_enemy_since_ms` / `_rise_after_ms` / `_sink`）/ 穿透掩码（`_set_pass_all(false)`）/ **准备期**（`_prep_until_ms = 0`，下一场由 `Roguelike._capture_zone_prep()` 重发） |
| **刻意不动** | 眩晕 / 定身 / 减速这三条**附加状态的计时**（§2.4 / §2.6 / §2.7）：它们是战场上已经发生的既成事实，且都很短（1~3 s）—— 本函数只管**位移与技能**层面的残留；`hp` / `max_hp` 也不动（回血是 `heal_to_full()` 的事） |
| 目前谁调 | **一处**：`Roguelike._recover_army()`（回合开始时，对我方每一队**还活着的每个槽位**调一次；阵亡的那些仍走"重新生成"那条路） |
| ⚠️ 不影响的东西 | 击退 / 眩晕 / 定身 / 技能位移一概照旧（它只写 `velocity` 的水平分量，且排在技能之后）；**建筑**（指挥所 / `is_no_attack()`）**永远不接路线**（用户口径是"所有**兵种**"） |

### 2.11 两个"纯视觉"机制（2026-09-27 新增，都不进判定）

> 来源：用户同日两条口径 —— "新增动画购买兵种时令这一队兵种从天上掉下来（匀速，只是动画，0.5s内播放完）"
> 与老账里的"影滩随待机浮动 / 触地尖梢受浮动影响"。
> ⚠️ 二者都**只改模型**（`Unit3D._visual` 及其子节点）⇒ 碰撞体 / 出生高度 / 判定 / 状态机一概不动。

| 项 | 口径 |
| --- | --- |
| **买兵掉落演出** | `Unit3D.play_drop_in(duration_ms, height)` + 四个字段 `_drop_until_ms`（绝对毫秒，I-13，`_ms` 后缀 ⇒ 自动进 `shift_deadlines()` 的暂停补偿）/ `_drop_total_ms` / `_drop_height` / `_drop_y`。**匀速**（线性，不是自由落体）：偏移 = 起始高度 × **剩余比例**；数值住 `GameConfig.UNIT_DROP_HEIGHT`（14.0 m）与 `UNIT_DROP_MS`（500）。⚠️ 偏移与"走路浮动 / 潜地下沉"**相加** —— 三人各写各的 `_visual.position.y` 分量，谁都不覆盖谁。⚠️ 参数**不给默认值**（跨脚本常量当默认值会踩 GDScript"必须是常量表达式"的限制）⇒ 调用方显式传 `GameConfig.*`。⚠️ 只有肉鸽**买兵**这条路调它（`Roguelike._play_drop_in()`，起手白送 / 复活 / 敌人都**不**演） |
| **贴地件（`GroundLock`）** | 模型里若有名为 `GroundLock` 的 `Node3D`（目前**只有影魔**建了它，挂影滩 / 十片影摆 / 拖尾），`Unit3D` 会在 `setup()` 里把它缓存成 `_ground_lock`，并在 `_process()` 里**反向抵消**走路浮动（`-absf(sin(...)) × UNIT_BOB_AMPLITUDE`）⇒ **身体照旧呼吸、影子始终贴地**。⚠️ 只减"浮动"这一项，**不减**潜地下沉 / 掉落偏移（那两项是"整个人一起动"，贴地件理应跟着）。⚠️ 这是"贴地件"的通名机制：以后别的兵种若有必须踩在地面上的件（脚底特效、影子），把它挂进同名节点即可，不必再动 `unit3d.gd` |

### 2.12 单位等级与击杀归因（2026-09-27 第四轮新增，**只有肉鸽用它**）

> 来源：用户"在肉鸽模式新增单位的等级，一队兵种的等级保持相同，最高9级。等级每增加1，攻击和血量就增加一倍"
> + 同轮澄清的**乘区规则**（原文）："**所有的百分比加成在同一乘区**（两个 +20% ⇒ +40%），
> 但**倍率（变为原来的几倍、增加几倍）均为独立乘区**（+20%、×2、×3 ⇒ 最终 **1.2 × 2 × 3 = 7.2** 倍）"
> 以及"倍率 = L（2 级 2 倍、9 级 9 倍）"。
> ⚠️ 与 §2.4 / §2.6 / §2.7 / §2.9 那些"附加状态"**不同族**：等级是**单位的常驻属性**（不随时间变），
> 只有玩家在准备阶段主动升级才会变。

| 项 | 口径 |
| --- | --- |
| 字段与倍率 | `Unit3D.level`（int，默认 **1**）+ `level_mult()` ⇒ `float(max(level, 1))`。⚠️ **上限 9 由调用方（肉鸽）把住**，本类只保证 ≥ 1 —— 别的模式不设它 ⇒ 恒为 1 ⇒ `level_mult()` = **1.0** ⇒ 行为与改动前**逐位相同** |
| 血量怎么算 | **统一一条式子**：`max_hp = (_hp_base + _hp_bonus_flat) × level_mult()`。`_hp_base` = `_ready()` 里记下的**原始**血量；`add_hp_bonus()` 从此只往 `_hp_bonus_flat`（**加法池**）累加（防御指令那种"基础血 × 12% × 级数"的平量正在这里）⇒ 与等级**天然分乘区**：`基础 × (1 + 百分比) × L` ✓ 正是用户那条规则。`_apply_hp_total()` 是**唯一**写 `max_hp` 的地方（除 `_ready()`），并**同步平移当前血**（`hp += 新上限 − 旧上限`）⇒ 已掉的血不会被升级补回来。`set_level()` 只做"改等级 + 重算" |
| 伤害怎么算 | **落在 `apply_hit()` 那一处入口**（近战 / 投射物 / 技能 / 溅射 / 传递伤害全走它）：`hit_amount = 面板伤害 × 攻击方队伍伤害倍率 × 攻击方 level_mult()`。⚠️ 两个倍率**相乘**（独立乘区）；⚠️ **`from == null` 的伤害源（陷阱 / 圈外内伤）不吃等级倍率** —— 没有攻击方就没有等级 |
| 升级 / 经验的归属 | **等级与经验住在"队"上**（`Roguelike.squads[i]` 的 `level` / `xp`），单位只是被动同步（出生与升级时各 `set_level()` 一次）⇒ "一队兵种的等级保持相同"由生成路径保证：**初次布阵 / 复活补位走同一个 `_spawn_one_squad_unit()`**，它先 `set_level(squad_level(index))` 再发防御加成 |
| 击杀归因 | `Unit3D._last_hitter`（**最后一个对我造成伤害的单位**）+ `killer()`。⚠️ 在 `apply_hit()` 里记，且只记"**敌对阵营**打来的"（自伤 / 无来源不算）；⚠️ **不改任何信号**（I-34 不受影响：`Events.unit_died(unit)` 照旧只带死者）；⚠️ `reset_to()` 会清掉它（归因不跨回合） |
| 目前谁用 | **只有肉鸽**：经验 / 升级 / 「精英招募」/ 敌方测试敌人的等级旋钮，见 `09_roguelike.md#6.6` |

### 2.13 肉鸽的"兵种科技"（2026-09-27 第十二轮新增，**只有肉鸽用它**）

>

### 4.1 配平算法（`GameConfig.make_match`）

1. 按轮次算出本轮总权重 `w`，**按权重预算**随机抽一支 A 队：反复从 `TYPE_ORDER` 里**等概率**抽兵种，
   抽中就把该兵种的 `weight` 从预算里扣掉（扇子兵/骑士/长弓手一次扣 2、**狂战士 3**、**轻骑兵（矛）5 / 火枪兵 5 / 火焰拳 5 / 影魔 5**、**投石车一次扣 10**（2026-09-25 第五条由 8 改回）、弩车一次扣 10、**武士大师 25 / 沙虫 25**），预算不足 1 点即停；
   ⚠️ 抽满**本轮的种数上限**之后，只允许从**已经抽过的这几种**里继续抽（2026-09-19 新规则）；
   ⚠️ **2026-09-26**：上限不再恒为 `MAX_KINDS_PER_TEAM`，而是按轮次取 `kind_cap_for_round()`（第 1 / 2 轮 = 1、第 3 / 4 轮 = 2、第 5 轮起 = 3），
   且前四轮还要**正好**等于该值（`exact_kinds_for_round()` ⇒ `make_match()` 里那一道 `base_kinds != exact` 的校验）。
   ⚠️ **沙盒专属兵种在抽签循环里被显式跳过**（`is_sandbox_only()`，目前只有召唤石柱）—— 它权重 999，混进来会当场破坏 I-20。
2. 在同一个重抽循环里再抽 B 队（**排除 A 队用过的兵种**），然后校验三条：① 双方的**种数**相同；
   ② 两队**总权重之差 ≤ `PAIR_WEIGHT_TOLERANCE`（1）**，且各自与本轮预算的偏差也 ≤ 1；③ 与 A 队**不重叠**。
   任一条不满足就**连 A 一起重抽**（2026-09-19 修正：原先 A 只在循环外抽一次，A 偏差过大时整轮必然全败）。
3. 重抽上限 `PAIR_RETRY_LIMIT`（200）次；用满仍不成立时依次降级并 `push_warning`：
   先放宽权重（返回第一对"种数相同且不重叠"的候选），连这种候选都没有才允许重叠。
4. 不再用评分挑对手（2026-09-19 用户要求**全随机**）：`_score()` 只服务于 `debug_balance_stats` 的
   ① 配平质量报告，不是优化目标。
5. 队伍成员打乱后交给 `make_spawn_layout()` 排布出生点（见 §4.3）。

**阵容评分公式**（2026-09-19 起**不再参与配平**，只用于 `debug_balance_stats` ① 的配平质量报告）：

```
score = Σ 单位 × (血量 × HIT_HP_MULT + 伤害×攻速 × (2.0 远程 / 1.4 近战))
```

> 这个公式是"排序用的近似"，不是精确胜率模型。改动它必须重跑 `debug_balance_stats` 回归。
> 实测配平质量（2026-09-19，`debug_balance_stats` ①）：第 1 / 4 / 7 / 10 轮平均评分差
> **549.4 / 1021.8 / 1353.0 / 2471.4**（最大 1074.8 / 2282.0 / 4144.0 / 5268.7）。
> ⚠️ 这个值现在**只是报告**（配平已改为全随机 + 允许 1 点偏差，不再以它为目标）；
> 差值随轮次人数增长而变大，属口径本身的特性。
>
> ⚠️ **2026-09-18 两处对齐代码**：①血量项由写死的 `×0.5` 改为**引用 `HIT_HP_MULT`**
> （倍率取消后即 ×1.0，会随不变量 I-24 自动变）；②删掉了原文多出来的 `×4`——
> 原文写"伤害×攻速×4×(2.0/1.4)"，而代码 `config.gd#_score()` 是
> `dps * 2.0` / `dps * 1.4`，**没有那个 4**。公式只用于排序，方向不受影响，但既然要改就一并对齐。

### 4.2 出生点布局（`GameConfig.make_spawn_layout`）

> 取代原来的"沿 z 轴一字排开"。属于**事实层面新增**的机制。

| 项 | 值 | 常量 |
| --- | --- | --- |
| 出生区 | 己方半场的**后半段**：`|x| ∈ [半宽×0.30, 半宽×0.95]` | `SPAWN_RANGE_NEAR/FAR` |
| 兵种簇心 | 每种兵 1 个；该兵种人数 ≥ 10 时开 2 个 | `make_spawn_layout` |
| 簇半径 | 3.4 m（同兵种在簇内均匀散开） | `SPAWN_CLUSTER_RADIUS` |
| 簇心间距 | 不同兵种簇心至少隔 4.0 m（采样 40 次；失败则退回随机点） | `SPAWN_MIN_SEPARATION` |
| 个体间距 | 同队选手之间至少 1.0 m（防止互相挡射界） | `SPAWN_MIN_GAP` |
| 出生高度 | 0.40 m（略高于地面，避免贴地判定抖动） | `spawn_height` |

**簇半径（3.4 m）大于簇心间距（4.0 m）的一半**，因此不同兵种的簇会互相重叠——
这是刻意的：用户要求"允许其他兵种穿插"，避免出现三个互不相干的方块。

实测（第 1 轮 10v10，100×50 场地的一次采样）：A 队 x∈[14.6, 33.1]、z∈[−23.0, 12.7]；
B 队 x∈[−48.0, −22.3]、z∈[−0.9, 22.3]，各自在自己的半场内。
硬边界由末两行的夹取决定（`|x| ≤ 48`、`|z| ≤ 23`），所以两军前沿相距 30 ~ 95 m。
