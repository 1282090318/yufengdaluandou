# 01 核心循环

> **权威范围**：玩家重复执行的动作、每一轮多长、反馈在哪一刻到达。
> 不含具体判定（→ `03_rules.md`），不含操作手感参数（→ `04_physics.md`）。

## 1. 核心循环定义

> 看阵型 → 押注 → 看打 → 结算 → 再押。

```
⓪ 开始界面（2026-09-25 新增：第一档只有「开始游戏」；见 05_ui_hud.md#9）
      ↓ 点「开始游戏」
⓪' 模式选择（同上第二档：「竞猜模式」/「沙盒模式」—— 同一套样式，不打飞也不渐黑）
      │
      ├─ 竞猜模式 ────────────────┐
      │                            ↓
      │                 ① 读阵（看两队名单与权重）
      │                            ↓
      │                 ② 下注（无时限：选一边，或观望）
      │                            ↓
      │                 ③ 观赛（镜头交给你，20~90 秒自动对战）
      │                            ↓
      │                 ④ 结算（押中 +点数 / 押错 −点数）
      │                            ↓
      │                 ⑤ 下一轮（回到 ①，最多 10 轮；点数归零即破产结束）
      │
      └─ 沙盒模式 ──> ①' 布兵（底部**兵种栏**选兵：左键点地面摆、**按住左键拖动可连摆一串**、**右键**收兵（按住右键拖动可沿途批量扫掉）；
                             顶栏两个「**清空**」分列左右，一点清掉那一队）
                            ↓
                      ②' 开战（自己点火：**没有押注、没有兴奋圈、没有 90 s 时限**）
                            ↓
                      ③' 打完（一方全灭）或按「结束战斗」
                            ↓
                      ④' 战果（**剩余总血量多的一方获胜**，无平局）→ 「重新布兵」回 ①'
                          ⚠️ 回 ①' 时**布局照旧**（原样重摆、血满、未点火），不用重摆
```

> ⚠️ **⓪ 与 ⓪' 只在"打开游戏"那一次发生**（整局只走一次）：它们**不是** `Game.Phase` 里的状态
>—— 这一刻 `Game` / `Hud` / `Sandbox` 都还没被装配，背景还是那张冻结的战斗演示；按下**模式**之后渐黑、
> 黑透那一刻才按所选模式换场，渐亮时竞猜模式已经是 ②（下注阶段）、沙盒模式已经是 ①'（布兵阶段）。
> **⓪ / ⓪' 不进任何回归**，也不改 ①~⑤ 与 ①'~④' 的任何时长。
>
> ⚠️ **两条循环互不相通**：沙盒**没有** ① 读阵（不掷阵容）、**没有** ② 下注、**没有** ⑤ 下一轮
>（它是"布兵 → 开战 → 战果 → 重新布兵"的闭环，**点数 / 观望机会 / 轮次一概不存在**）；
> 竞猜模式那边也**看不到**兵种栏与「开战」。两者的口径见 `03_rules.md#10` 与 `05_ui_hud.md#11`。
> ⚠️ 沙盒那一环**记得住布局**：`Sandbox._layout` 是布兵的**唯一记账**（队别 / 兵种 / 落点），
> 所以 ④' 回到 ①' 时会把原样摆回来（血满、未点火）—— 用户 2026-09-25："**战斗完毕后应保留之前的布兵布局**"。
> 玩家想换布局时用顶栏的「清空」（清掉一队的那一批）或右键逐个收掉（**按住右键拖动可沿途批量扫掉**），**不必**从零重摆。
>
> ⚠️ **2026-09-25 起，①~⑤ 随时可以被打断**：`Esc`（或顶栏齿轮）唤出**暂停菜单** ——
> 「继续」**原地继续**（瞬间，无过渡）；「重新开始」把这一局整个扔掉、回到 ②（点数回 10000、机会回 3、回第 1 轮）；
> 「主菜单」直接回到 ⓪ 那一屏（**不保存战斗**）。后两者都是**渐暗 → 黑透换场 → 渐亮**。
> 口径见 `05_ui_hud.md#10`，流程与"暂停要补偿绝对时刻"的坑见本文 §8。

## 2. 循环分层

| 层级 | 实际时长 | 玩家在做什么 | 反馈形式 |
| --- | --- | --- | --- |
| 微循环 | 0.3–3 s | 盯某一场局部交战，判断谁先倒 | 血条下降、击退位移、盾牌挡箭火花 |
| 中循环 | 20–90 s | 看完整场比赛，验证自己的判断 | 存活人数 / 总血量实时变化 |
| 宏循环 | 决策（无时限）+ 10~15 s 比赛 ≈ 1 轮 | 一轮决策 + 一场比赛 | 点数增减、观望机会扣减、结果浮层 |
| 元循环 | 10 轮 ≈ 10–15 min | 一整局观赛 | 结束评定：点数、押中率、"点生点" |

## 3. 单场比赛节奏（固定时间轴）

| 时刻 | 事件 | 玩家感受 |
| --- | --- | --- |
| 0 s | 双方从东西两侧出发区冲向中线 | 阵型展开，一眼看出兵种克制 |
| 0–20 s | **前段是接敌行军**：场地放大到 100×50 后两军前沿相距 30~95 m（短弓手射程 16 m、**长弓手 28 m**），接触后才转入交战 | 主要击杀仍集中在这段；平均比赛时长由 52×24 时代的 12~14 s 升到 **18~24 s**（逻辑层回归口径） |
| 20 s | 若双方 0 次命中且已过 20 s → **僵持判平**（防弓箭手无限风筝） | 极少触发 |
| 90 s | 强制结束，按剩余总血量判定；完全相同则平局 | 收尾 |

> ⚠️ **2026-10-23**：兴奋圈已废止。上表不再有 60 秒收圈，也不再有圈外攻速和内伤。旧节拍留在 `99_decisions.md`。

## 4. 反馈清单

- [x] 每个攻击动作有即时视觉反馈（武器前摇抬起 → 命中帧落下）
- [x] 受击有即时视觉反馈（全身闪白 140 ms）
- [x] 状态变化可累积可见：血条实时下降，未满血才显示
- [x] 失败可归因：结算写清"一方全灭 / 时间到·比剩余血量 / 僵持判平"
- [x] 成功有超预期奖励：ALL 押中时额外奖励翻双倍，浮层单独文案
- [ ] 待补：音效与镜头震动只在结算时有一次轻微 shake（`06_audio.md` 未实现）

## 5. 决策压力设计

> ⚠️ 2026-09-17（优化 2）：**倒计时已整个取消**。玩家不选就一直等，游戏不会替他做决定。
> 这抽掉了原本的"信息不足 + 时间压力"张力，目前剩下的压力来自**点数会被打光（破产）**与**递增投入**。

| 机制 | 数值 | 目的 |
| --- | --- | --- |
| 决策时限 | **无**（想清楚再点） | 让玩家有充分时间读阵型 |
| ~~系统倾向~~ | **已删除**（2026-09-18，任务 6.2） | 卡片不再显示"系统推荐"标记；新手锚点回到"自己读名单" |
| 唯一出口 | 按钮里的 `观望`（不输不赢，但仍要看一场，且**消耗 1 次观望机会**） | 保留"不押注也要付出代价" |
| 真正的压力来源 | **点数归零即破产** + 每轮投入递增（**第 3 轮起可 ALL**，2026-09-18 由第 6 轮提前） | 一次押错就可能把点数打到下一轮固定投入以下 |

**已删除的机制**（历史，见 `99_decisions.md`）：

- `DECIDE_LIMIT_MS` 20 s 决策时限
- `AUTO_PICK_AT_MS` 超时自动观望
- `HIDE_SUPPORT_MS` 末段隐藏系统倾向（防跟票）

> **复活条件**：如果实测发现"没有时限 ⇒ 玩家反复犹豫、观赛节奏被拖断"，
> 应优先考虑"给一个手动触发的提示"而不是把倒计时加回来。

## 6. 反模式（本作明确避免）

- ❌ 循环里出现"玩家只能等，没有任何选择"——即使不押注也要选"观望"
- ❌ 反馈延迟超过 200 ms 且没有补偿动画
- ❌ 结算只给一个数字，不给出归因（必须写清谁赢、为什么赢）
- ❌ 让玩家可以重开**某一轮**（会摧毁"点数会被打光"的全部张力）
  ⚠️ **2026-09-25 澄清**：pause menu 的「重新开始」是**重开整局**（点数 / 轮次 / 阵容全部回到开局），
  **不是**重开某一轮 ⇒ 本条**仍然成立**、没有被推翻；两者别混为一谈（见 §8 末尾那段）。

## 8. 暂停与重开（2026-09-25 新增）

> 用户口径："在战斗过程中也可以按 esc 来唤出界面，且**此时暂停**，按继续则继续战斗，**退到主菜单不保存战斗**"。
> UI 细节（齿轮位置、按钮样式、过渡时长）见 `05_ui_hud.md#10`；相位规则见 `03_rules.md#5` 与 `#7`。

| 动作 | 行为 | 过渡 |
| --- | --- | --- |
| **暂停**（`Esc` / 顶栏齿轮） | `get_tree().paused = true`：单位 / 兴奋圈 / 镜头 / 计时全停；**相位原地不动** | 无（菜单直接出现） |
| **继续** | 解除暂停，**原地接着打** | 无（用户要求"瞬间"） |
| **重新开始** | **整局重置**：点数回 10000、观望机会回 3、回第 1 轮、重抽两队（`setup_first_round()`） | **渐暗 620 ms → 黑透换场 → 渐亮 760 ms** |
| **主菜单** | 拆掉比赛、回到**开始界面**那一屏（演示场景重新预演 + 渐亮）；**不保存战斗** | 同上 |

> ⚠️ **2026-09-25 起，菜单里的"中间那一项"随模式与相位而变**（`PauseMenu` 只固定「继续」与「主菜单」）：

| 模式 / 相位 | 菜单里的选项 | 依据 |
| --- | --- | --- |
| 竞猜（押注 / 战斗 / 结算） | 继续 / **重新开始** / 主菜单 | 既有口径不变 |
| 沙盒 **布兵阶段** | 继续 / 主菜单 —— **没有「重新开始」** | 用户口径："布兵阶段按 `Esc` 不许出现「重新开始」" |
| 沙盒 **战斗阶段** | 继续 / **结束战斗** / 主菜单 | 用户口径："「重新开始」变成「结束战斗」"（立刻停手 + 按剩余总血量判胜） |
| 沙盒 **结果阶段** | 继续 / 主菜单（战斗已经结束，中间项没有对象） | — |
| **肉鸽**（准备 / 结算） | 继续 / 主菜单 —— **同沙盒布兵阶段那条理由**：玩家正在花钱，不许出现「重新开始」 | 2026-09-26 新增模式 |
| **肉鸽 战斗阶段** | 继续 / **结束回合** / 主菜单（`Roguelike.end_round()`：立刻结算本回合，并**自己解除暂停**） | 用户口径：中间那一项随模式与相位变 |

> ⚠️ **三个模式的暂停 / 恢复走同一条实现**（`core/match_pause.gd`）：树暂停不停表（I-13），
> 恢复时把暂停时长从所有绝对时刻里扣掉；「结束战斗」由 `Sandbox.end_battle()` **自己解除暂停**
>（`PauseMenu` 不补第二次 `resume_match()`，否则时长会被扣两遍）。

> ⚠️ **"暂停"不是 `Game.Phase` 的一员**：它是横切在 ①~⑤ 之上的一个叠加状态（树暂停），所以
> **不产生任何结算**（不判胜负、不发点数、不消耗观望机会）。
>
> ⚠️ **本项目最容易做错的一点**：所有计时都是**绝对毫秒**（不变量 I-13），而**树暂停不会停表** ⇒
> 暂停 N 秒后，"赛程倒计时 / 出手冷却 / 技能冷却 / 眩晕 / 冲刺时长"都会凭空过去 N 秒。
> 所以恢复时必须把**所有绝对截止时刻整体后移 Δ**（`Game.resume_match()` → `Arena` / `CameraRig` / `Unit3D`
> 的 `shift_deadlines()`；单位那侧是**属性扫描**所有 `_*_ms` 字段）。实测：暂停 0.9 s ⇒ `match_start_ms`
> 后移 **916 ms**，暂停期间单位位移 **0.000000 m**。
>
> ⚠️ **和 §6 那条反模式的区别**（别把它们混为一谈）：§6 禁止的是"**重开某一轮**"（用当前点数重摇一次，
> 那会摧毁"点数会被打光"的张力）；这里的「重新开始」是"**把整局扔掉、从第 1 轮重来**"，
> 代价是当前全部进度（点数 / 轮次 / 阵容）—— 两者不是一回事。
