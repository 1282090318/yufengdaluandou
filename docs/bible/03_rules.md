# 03 规则（胜负判定、数值边界）

> **权威范围**：怎么算赢、怎么算输、点数和机会怎么变、每个数值的上下界。
> 代码落点：`scripts/game/game.gd`（流程与结算）、`scripts/core/config.gd`（数值）。

## 1. 胜负判定

> ⚠️ **适用范围（2026-09-25 起）**：本节 WIN-01 ~ DRAW-03 **全部只描述竞猜模式**。
> **沙盒模式只有一条判定**：一方全灭、或玩家按「结束战斗」⇒ **剩余总血量多的一方获胜，没有平局**
> （见 §10）。它连 `Arena.start_match()` 都不调用 ⇒ 90 s 时限 / 僵持判平 / 平局判定这三条在沙盒里
> **根本不会执行**（`arena.gd#_physics_process` 整个被 `match_active` 闸门挡在后面）。
> 这条豁免是用户在 2026-09-25 明确裁决的，见 `_index.md#2.3` 开头的说明与 `99_decisions.md` 同日条目。

### 1.1 判定表

| ID | 条件 | 判定时机 | 结果 |
| --- | --- | --- | --- |
| `WIN-01` | 对手全部阵亡 | 每物理帧 | 存活方获胜，`reason = "wipe"` |
| `WIN-02` | 90 s 到点，剩余总血量多的一方获胜 | 每物理帧 | `reason = "timeout"` |
| `WIN-03` | 90 s 到点，总血量完全相同，则比**血量比例** | 每物理帧 | `reason = "timeout"` |
| `DRAW-01` | 双方同时全灭 | 每物理帧 | 平局，`reason = "draw"` |
| `DRAW-02` | 血量与血量比例都相同 | 每物理帧 | 平局，`reason = "draw"` |
| `DRAW-03` | 双方均已 20 s 没有任何命中（僵持，通常发生在只剩远程互相追不上） | 每物理帧 | 平局，`reason = "stalemate"`，**早于 90 s 触发** |

### 1.2 判定顺序（同一帧多种条件同时成立时）

1. `DRAW-01` 双方同时全灭 → 平局（平局优先级最高，避免"谁先死谁输"的帧序偏差）
2. `WIN-01` 单方全灭 → 对方获胜
3. `DRAW-03` 僵持 → 平局
4. `WIN-02` / `WIN-03` / `DRAW-02` 时间到结算

### 1.3 平局的处理（不变量 I-25）

- 平局时**押注全额返还**，点数不变。
- 平局**不消耗机会**。
- 原因：原作里"两队同时被击败时押两边的观众都算押中"；本作没有"两边都押"的选项，因此对等处理为返还。

### 1.4 结算与押注的对应关系

| 比赛结果 | 点数 | 观望机会 |
| --- | --- | --- |
| 押中 | `+ 投入 × 1.0`（ALL 时 `+ 投入 × 2.0`） | 不变 |
| 押错 | `− 投入`（**扣到 0 即破产，立刻结算**） | 不变（2026-09-18 改：押错不再消耗机会） |
| 平局（押了） | 不变（全额返还） | 不变 |
| 平局（观望） | 不变 | 不变（机会已在按下"观望"时扣掉） |

### 1.5 阵营转换：心灵腐化（2026-09-25 新增）

> 用户口径："新增单位：心灵腐化师……拥有技能：心灵腐化（被动）：攻击不会使敌方失去生命，而是给敌方
> 叠加『心灵腐化值』。**心灵腐化值**：当一个单位的心灵腐化值**大于自身剩余血量**时，
> **自动变成另一方的单位（保留血量）**。心灵腐化值会在没有心灵腐化师攻击的情况下自动清空"。
> ⚠️ 这是本作**第一条"单位中途换边"的规则** —— 它直接改动"双方各有哪些人"这件事，所以写在这里
> （与 §1.1 的 `WIN-01`／沙盒的"剩余总血量"判据同层），细节与常量见 `02_entities.md#2.3` 与 `04_physics.md#5.2`。

| 项 | 口径 |
| --- | --- |
| 腐化值从哪来 | 心灵腐化师的攻击**不掉血**，把"伤害数值"（10）**原样当腐化值加上去** ⇒ 攻速 **7/s** ⇒ **70 腐化值/s**（⚠️ **2026-09-26**：攻速 8 → 7，用户："心灵腐化师攻击力：40变成35" —— 按 ×0.875 削腐化速度、"每跳仍 10"；面板间隔 0.125 → **≈0.143 s**）。⚠️ 走的是 `Unit3D.apply_hit()` 里的**分流**（判据 `is_corruptor()`），所以它对**一切伤害来源的形状**都是透明的：近战结算与投射物命中都一样 |
| 换边判据 | `腐化值 > 剩余血量` ⇒ **整队换边、保留血量**。⚠️ 是**严格大于**（等于不换，与用户原话逐字对齐）。⚠️ **2026-10-02**：策反者买了「强化控制」时，换边之后把血回满。没买这条时仍保留换边前的血 |
| **换边要同时改三处** | ① `team`（索敌 / 扇形群伤 / 结算都读它）② **碰撞层** `1 << (team + 1)`（不改的话它会被"原来那队"的箭继续判定、也继续挡住原来那队的人）③ **外观**（模型底色与血条贴图色都取 `GameConfig.team_color(team)`）。另：换边后**旧目标必然是友军** ⇒ 立刻丢锁、下一帧按新阵营重新索敌；"穿队友"的掩码也要按新队重算 |
| **对胜负的影响**（用户裁决） | **血量跟人走**：被转化者的剩余血量计入**新队** ⇒ 沙盒的"剩余总血量"会因此翻转；**原队场上清零 ⇒ 判"一方全灭"**（与 §1.1 的 `WIN-01`、沙盒的"一方全灭"是**同一条判据**）。实测（沙盒）：转化后结算 `hp = [326, 0]`、`weight = [10, 1]`、`winner = 0`、`alive = [2, 0]`，相位转 `RESULT` |
| **谁能被腐化** | **没有免疫**（用户裁决"都能被腐化"）—— 沙虫、武士大师、投石车、弩车**都照叠**，与"免疫眩晕"那条 `is_stun_immune()`（boss ∪ 载具）**无关**。⚠️ **2026-09-25 第四轮（用户："无敌不会免疫心灵腐化值"）：`is_invulnerable()` 也不再是例外** —— 腐化分流已被**提到无敌闸门之前** ⇒ **腐化绕过无敌**：滞空中的狂战士、拔刀斩中的大师、**影子形态里的影魔**照样被叠、叠够了照样被策反（既有的"无敌 = 一切来源都打不进来"因此收窄为"**只挡伤害**"，与"无敌不免疫击退"那条同源）。⚠️ 沿革：本行原先写的是"无敌时连腐化值也叠不上（刻意按既有口径办）"——**那句已作废**。⚠️ **2026-10-03**：肉鸽指挥所除外。照到它不叠腐化值，这一跳改成扣血（仍是这一跳的伤害数值，等级和队伍伤害倍率照常乘）。指挥所不会被策反。⚠️ **2026-10-03**：道具魔法盾和兵种「庇护」挡住穿过圆边界的这一跳，目标不叠腐化、也不掉这下血，盾自己掉血。人在圆里面、射线没有穿出边界时，仍然照得到。这不是单位身上的免疫 |
| 清空时机 | **停照即清**：最近一次被照射距今超过 `UNIT_CORRUPT_HOLD_MS`（**200 ms**）就归零。⚠️ 这个宽限**必须大于一个照射间隔**（8/s ⇒ 125 ms），否则连续照射期间会被自己的间隙清掉 —— 用户那句"**只要存在至少一个心灵腐化师在攻击他就不会清零**"正是这条 |
| 换边之后 | 腐化值**立刻归零**（否则下一次判据会当场再触发一次）；这道激光也**到此为止**（用户："直至这名目标离开范围或**变成友方**"） |
| 表现件 | 目标身上多一条**腐化条**（紫色、挂在血条上方，比例 = 腐化值 / 血上限，见 `05_ui_hud.md#6.1`）；腐化师手上射出一道**激光光束**（见 `04_physics.md#5.2`） |
| 观望 | 不变 | **− 1**（按下按钮时扣，见 2.1） |

### 2.1 观望机会的消耗时机（2026-09-18 改）

> **`observed = (bet_team < 0)` 是"有没有下注"的唯一判据**，与比赛结果无关。

| 结算 | 观望机会 | 点数 | `tag` |
| --- | --- | --- | --- |
| **观望**（未下注） | **− 1**（在按下"观望"时扣，不是结算时） | 不变 | `观望` |
| 押中 | 不变 | `+ 投入 × 1`（ALL 时 ×2） | `押中` / `全力支持命中·双倍奖励` |
| 押错 | **不变** | `− 投入` | `押错` |
| 平局（押了） | 不变 | 全额返还 | `平局返还` |
| 平局（观望） | 不变（已在按下时扣过） | 不变 | `观望` |

> ⚠️ **2026-09-18（轮 C）**：原规则是"押错消耗 1 次机会"，机会等于"三条命"。
> 现在机会改成**观望配额**——想多看一轮再下注就得付一次；押错**只赔点数**。
> 理由是押错已经有"掉点数"这一层惩罚，不该再叠一条命（不变量 I-21，见 `99_decisions.md`）。
>
> ⚠️ 历史（2026-09-17）：观望曾因 `bet_team = -1` 走进"押错"的 `else` 分支而白掉一次机会，已修。

> **张力来源已转移**：现在唯一能终结一局的是**点数归零（破产）**。押错让点数变薄、押中让它变厚，
> `ALL` 把这两个方向同时放大（`03_rules.md#7-边界情况`）。

  （修 BUG：此前 HUD 的开关跨轮、跨局都不清，新开一局时会停在第 1~2 轮"ALL 按钮禁用、想关也关不掉"的死状态。
  玩法侧本来就没问题——`Game._enter_betting()` 每轮都清 `bet_all_in`；坏的是 HUD 的开关状态。）
- **强制全力支持**：**剩余点数 < 本轮固定投入时，按下"支持"即按 ALL 处理**，

- 其余情况投入会被 `clamp(投入, 0, 当前点数)` 夹取。
- 观望：不投入、不输不赢，但**仍然要看一场比赛**（结果照常结算，只是不涉及点数）。

## 5. 状态机（对局层）

| 状态 | 进入条件 | 允许的动作 | 退出条件 |
| --- | --- | --- | --- |
| `INIT` | 启动 | — | `setup_first_round()` → `BETTING` |
| `BETTING` | 每轮开始 / 下一轮 | 加注、ALL、观望 | **只有玩家操作**才会退出（无倒计时、无超时） |
| `FIGHTING` | 双方已生成并就位 | 只能看与自由切镜头 | 分出胜负 → `ROUND_RESULT` |
| `ROUND_RESULT` | 结算完成 | 看结果 | 点"下一轮"→ `BETTING`；**点数归零（破产）**或打满 10 轮 → `GAME_OVER` |
| `GAME_OVER` | 结束 | 看总结 | 点"再来一局"→ 重置为 `BETTING` |

**转换优先级**：`GAME_OVER` 只在结算之后判定一次，不允许在 `FIGHTING` 中直接跳到 `GAME_OVER`。

> ⚠️ **沙盒模式有它自己的一套三相位状态机**（`Sandbox.Phase`，2026-09-25 新增）：
> `PLACING`（布兵）→ `FIGHTING`（开战）→ `RESULT`（一方全灭的战果），点「重新布兵」回到 `PLACING`。⚠️ **2026-10-23** 手动「结束战斗」不进战果，直接回到 `PLACING`。

## 6. 物理交互判定

### 6.1 近战命中

```
距离(自身, 目标) <= 射程 × 1.18   →   命中
```

`1.18` 是宽容系数（`unit3d.gd#CONTACT_RATIO`）：长矛的击退会把目标瞬间推出射程，不留宽容会出现"打到了却不掉血"。

### 6.2 弓箭命中

箭矢每帧做"上一帧位置 → 本帧位置"的线段查询（`arrow.gd#_raycast`），优先判定盾牌。详见 `04_physics.md#7`。
> ⚠️ **例外（2026-09-19 起为两个）**：**弩车的大型弩箭**与**投石车的石弹**无法被盾牌阻挡（`ignores_shield`），判定直接跳过盾牌分支（详见 `04_physics.md#7`）。

### 6.3 伤害结算

```
实际伤害 = PROFILES[type].damage × HIT_ATK_MULT   # 2026-09-18 起 HIT_ATK_MULT = 1.0，即不再缩放
实际最大生命 = PROFILES[type].hp × HIT_HP_MULT     # 同理 HIT_HP_MULT = 1.0
生命 clamp 到 [0, max_hp]
```

> 倍率取消（I-23 / I-24 = ×1.0）之后，**公式仍然成立，只是系数为 1**——
> 保留乘法是为了以后想重新引入全场缩放时不用改代码结构。
> ✅ **代码已同步**：`config.gd` 的两个倍率都是 **1.0**，等式右边就是表值本身。
> ⚠️ **2026-09-27（肉鸽的单位等级）**：肉鸽那一路还有两个**后乘的独立乘区**（`02_entities.md#2.12`）——
> `实际伤害 = 面板伤害 × 队伍伤害倍率（进攻指令 / 指挥所减益）× 攻击方等级 L`，
> `实际最大生命 = (原始血 + 加法池) × 等级 L`。⚠️ 它们**只在肉鸽生效**（别的模式 `level` 恒为 1 ⇒ ×1.0），
> 且**不进配平评分**（`score()` 仍按表值算，见 §4.1）—— 所以上面两行对另外两个模式**逐字仍然成立**。
> ⚠️ **另有"表值只是基准、实际出手另算"的两个兵种**（与上面那条乘区**无关** —— 它们改写的是**基准本身**）：
> **影魔 `shadow`「时候已到」**（距上次出手每秒 +80、封顶 320，见 `02_entities.md#2.3`）与
> **湮灭之瞳 `doom_eye`「能量汇集」**（对同一目标每 4 下一档：30 → 90 → 300 → **1000**，见 `02_entities.md#2.3`。⚠️ **2026-10-02** 第四档才是 1000；在此之前第三档从第 9 下起一直是 300）。
> ⇒ 读这两行的表值时别忘了它们；⚠️ `debug_balance_stats` 把影魔按在 0 加成上（"持续平 A"正好是最差情形）、
> **完全不建模湮灭之瞳的阶梯**（表里它永远等于 30）⇒ 两张表都会**低估**这两个兵种。

## 10. 沙盒模式（2026-09-25 新增）

> 用户口径（逐条落进本节的依据）："**玩家自由摆放兵种而不是随机生成**；**下方是兵种栏**选要放什么；

### 10.1 与竞猜模式的唯一分界（⚠️ 这一条最容易做错）

| 项 | 口径 |
| --- | --- |
| **不启赛程** | 沙盒**从不调用 `Arena.start_match()`**（那一支的语义是"启动赛程"：`match_active = true`）。它改用 `Arena.start_skirmish()` —— **只让摆好的单位能动**，`match_active` 保持 false |
| **沙盒战斗时钟** | ⚠️ **2026-09-26 起 `start_skirmish()` 还记一个 `skirmish_start_ms`**（`skirmish_elapsed_ms()` 读它，**返回 −1 = 没在战斗**）：它是"**开战那一刻**"的绝对毫秒，**唯一用途**是给召唤石柱的技能当节拍锚点。⚠️ 它与 `match_start_ms` **刻意分开**——沙盒从不启赛程，借那个字段的话石柱一辈子召唤不出东西。⚠️ `stop_skirmish()` / `settle()` 把它归零；`Arena.shift_deadlines()` 把它一起平移（暂停期间不欠账） |
| **沙盒专属兵种** | ⚠️ **2026-09-26 起 `PROFILES[*]["sandbox_only"]` 是一个正式标记**（判据 `GameConfig.is_sandbox_only()`，目前只有召唤石柱）：竞猜模式的抽签（`_random_composition()`）**显式跳过**它们 ⇒ 它的权重（999）**永远不会**进竞猜配平、也永远不会破坏 I-20 / I-27。⚠️ 沙盒这一侧**不限数量、不看权重**（顶部那行"总权重"因此可能读到 999 的倍数） |
| 因此**整体失效**的东西 | 兴奋圈收缩 / 90 s 时限 / 僵持判平 / 平局判定 / **单位"兴奋"状态**（`_update_excited()`）—— 它们全在 `arena.gd#_physics_process` 的 `match_active` 闸门之后。⇒ 摆完不打也不会超时、圈永远不出现、双方同归于尽也不会有"平局" |
| 结束条件 | **只有两条**：① 一方全灭（每物理帧数人头，`Sandbox._physics_process`）进战果；② 玩家按「结束战斗」直接回到布兵，布局照 `_layout` 重摆。⚠️ **2026-09-26 起场上还会多出"召唤物"**（石柱招的），全灭仍把它们算进人数和剩余总血量 |
| 胜负判据 | **剩余总血量多的一方获胜**（`Arena.team_hp()`）。全灭与手动结束**用同一条判据**；总血量相同 ⇒ 显示「同时全灭」（见 §7）。⚠️ **召唤物算在召唤者那一队**（`team_hp` / `alive_count` 按 `unit.team` 统计，与它们是不是"玩家摆的"无关） |
| 收兵 | `Arena.stop_skirmish()`：结果展示期间所有单位与箭矢停手（与 `_finish()` 里那两行同义，但**不复用** `_finish()` —— 它带 `match_ended` 与"只结一次账"的闸门，会牵动 `Game` 那套结算）。⚠️ 它同时把沙盒战斗时钟归零 ⇒ 石柱停止召唤 |

### 10.3 相位与相机

| 相位 | 进入 | 相机（**全部复用 `CameraRig` 现成的那几支，不另摆机位**） | 暂停菜单的中间项 |
| --- | --- | --- | --- |
| `PLACING` | 装配完成时 `Sandbox.begin()`；结果页点「重新布兵」；或战斗中点「结束战斗」 | `on_betting_phase()` —— 与竞猜押注同一套默认机位（`CAM_QUIZ_PITCH`）+ 光标可见。见 `05_ui_hud.md#7.3` | **无**（用户口径） |
| `FIGHTING` | 「开战」按钮（要求两边各至少 1 个兵） | `on_fight_phase()` —— 与竞猜模式开赛同一支（光标锁进窗口 + 平滑到指挥视角） | 「**结束战斗**」 |
| `RESULT` | 一方全灭 | `on_round_result()` —— 与竞猜模式"一轮打完"同一支（放出光标，机位不动） | 无（战斗已经结束） |
